# Proposal

## Why

编辑器启动时会先恢复本机草稿，项目越大（页面、歌名、图片资产越多），IndexedDB 读取、结构校验与图片解码耗时越长。当前这段时间画面停在静态的「从左侧导入歌单，再把分类拖到页面上」空态提示上，用户无法判断是应用没反应还是正在恢复草稿，容易误以为数据丢失或重复导入。

## What Changes

- 在画布中央增加启动载入提示：应用启动、恢复本地草稿期间显示「正在载入本地草稿…」及轻量载入动效，明确当前处于载入过程。
- 载入提示存在时 MUST NOT 显示「从左侧导入歌单」空态提示；载入结束（无论成功、无草稿还是失败）后，再由既有空态/内容渲染逻辑接管。
- 载入提示使用静态 HTML + 过早显示策略，避免首帧先闪出空态提示；不改变现有的草稿读取、校验、迁移与错误提示流程。
- 载入提示遵守系统「减少动效」偏好；载入状态通过礼貌播报区域对辅助技术可见。
- 载入提示只属于编辑界面，不进入 PNG 导出。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `project-persistence`: 在「草稿启动恢复」中补充启动载入反馈：恢复期间显示画布中央载入提示、隐藏导入空态、结束后移除提示；无草稿或恢复失败时平滑回到既有空态与提示行为。

## Impact

- `index.html`：新增启动载入提示节点，并让空态提示默认隐藏，避免首帧闪出错误引导。
- `style.css`：新增载入提示与载入动效样式，复用现有画布中央空态提示贴的定位与配色语言，并接入 `prefers-reduced-motion`。
- `js/ui.js`、`js/app.js`：在启动恢复前后切换载入提示可见性；不改变草稿存储格式、项目 JSON、导出流程或零构建运行方式。
- 测试：现有纯逻辑回归套件不覆盖 DOM/启动 UI，需补充浏览器手动或 `agent-browser` 场景验证（有草稿启动、无草稿启动、损坏草稿启动、减少动效）。
