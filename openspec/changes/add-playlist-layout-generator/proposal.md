# Proposal

## Why

需要一个纯前端、零构建的歌单排版工具：导入本地文本歌单，在自由画布上把分类排成适合手机分享的版面，并导出 PNG。现有工具要么依赖构建/后端，要么不能按“分类块 + 表格 + 背景层”的方式排版。

## What Changes

- 新增单页 Web 应用，可直接 `file://` 打开，无构建、无服务器。
- 文本歌单导入：UTF-8/GBK、BOM、`#分类`、未分类、重名校验、重复导入覆盖并按分类名保留版面。
- 多页自由画布：全局页面尺寸/边距、页签增删切换、背景层 + 内容层、自由文字/图片、z-order。
- 分类块：分类名/歌名两个子分区，字体/字号/粗细/颜色/行距；歌名表格支持列/行、动态行、列优先/行优先、按虚拟字数排序、自动/手动列宽、红格溢出警告、自动续表。
- 背景层：本地图片、原大小/横向/竖向/cover、透明度、模糊、填充色；新页可沿用上页背景并共享图片资产。
- 项目 JSON 保存/加载（图片 base64、按内容去重）；当前页 PNG 导出（指定尺寸、裁剪页面边界、隐藏编辑辅助）。
- 本地 vendor LeaferJS UMD，保持零构建；更新 `AGENTS.md` 的依赖说明。

第一版不做：分类跨页续排、应用内拆分分类、歌曲文本编辑、自由元素旋转、自由图片裁剪/模糊、多选、撤销/重做、草稿自动保存、全部页打包导出、`#` 开头歌名的转义。

## Capabilities

### New Capabilities

- `playlist-import`: 文本歌单的解码、解析、重名校验，以及重复导入时按分类名保留版面的合并规则。
- `page-editor`: 多页自由画布、全局页面尺寸/边距、页签管理、背景/内容两层、自由文字与图片、选择与 z-order。
- `category-layout`: 分类块与歌名表格的排版规则，包括虚拟字数排序、填充顺序、动态行、列宽、溢出警告和自动续表。
- `background-layer`: 每页背景图片的导入、尺寸模式、透明度、模糊、填充色，以及跨页共享图片资产。
- `project-persistence`: 项目 JSON 的保存/加载、图片资产 base64 与内容去重。
- `png-export`: 当前页按指定尺寸导出 PNG，裁剪页面边界并排除编辑辅助。

### Modified Capabilities

无。项目目前没有已存在的 specs。

## Impact

- 新增 `index.html`、`style.css`、`js/` 下的模型/导入/布局/渲染/UI/导出代码，以及 `vendor/` 下的 LeaferJS UMD。
- 不引入构建步骤、服务器、包管理器或 CDN 运行时依赖；保持 `file://` 可打开。
- 仅考虑 Chrome；图片和文本读取依赖浏览器 File API。
- `AGENTS.md` 的“零依赖”需改为“零构建 + 本地 vendor 的 Leafer UMD”。
- `opencode.json` 已加入 Context7 MCP，仅用于开发期查文档，不属于应用运行时。
