# Proposal

## Why

把分类添加到页面时，新分类块的纵向位置会参照页面上全部内容物件，包括自由文字和自由图片。当页面里有一张位置靠下的图片时，点击分类（或把分类拖到图片下方）会把新分类块推到图片底部，甚至挤出页面，而用户期望分类块只按已有分类块堆叠。分类流与自由素材是两条互不干扰的排布线，定位计算应只认分类块。

## What Changes

- 分类块定位的候选集合由"页面全部内容物件"收窄为"页面内全部分类块"；自由文字与自由图片不再参与纵向定位计算。
- 保留鼠标 Y 语义：拖放时仍取"鼠标上方最低分类块底边"，没有分类块位于鼠标上方时取页面上边距；点击/键盘添加等同于鼠标位于所有分类块下方，落到最低分类块底边。
- 由此产生的新行为：新分类块可以与自由图片/文字重叠，也可能落在只看素材时显得"靠上"的位置；这是"只按分类块堆叠"的预期结果。
- 抽出纯函数承载该计算，使其进入 Node 回归套件覆盖范围；拖放创建与点击创建共用同一实现。
- 不改变同一分类最多一个块、默认宽度、左边缘对齐等既有约束。

## Capabilities

### New Capabilities

（无）

### Modified Capabilities

- `category-layout`: 「分类块放置」需求的纵向定位规则由"所有内容物件"改为"所有分类块"，并反转「物件类型不限于分类块」场景、新增"分类块与自由图片混排"和"仅有自由物件"的场景。

## Impact

- 代码：`js/app-interactions.js`（`categoryDropPosition` 候选集过滤）、`js/app.js`（点击/键盘放置入口改为调用共用的纯函数）、`js/layout.js`（新增放置位置计算纯函数）。
- 测试：`scripts/checks/layout.test.js` 新增覆盖；现有 Node 套件 `node --test scripts/checks/*.test.js` 无其他改动。
- 规格：`openspec/specs/category-layout/spec.md` 的放置需求与相关场景。
- 不涉及数据模型、持久化格式、导出结果或运行时依赖。
- 已知相邻缺陷不在本变更范围：拖放创建分类时缺少 `pushUndo('放置分类')`（点击路径已有），撤销行为不一致，另行处理。
