# Proposal

## Why

现在往页面里加自由图片只能点“添加图片”再选本地文件。截图、从聊天工具复制的图片本来就已经在剪贴板里，用户却得先存成文件再选一次，多出一步且容易留下临时文件。粘贴是这类素材最自然的入口，并且将来背景、其他图片位置也可能需要同样的剪贴板读取能力。

## What Changes

- 增加 `Ctrl + V` 粘贴图片：当焦点不在文本输入/编辑控件内、且没有打开模态对话框时，从剪贴板读取图片并添加到当前页，作为自由图片元素。
- 粘贴图片复用现有图片资产管线（去重、base64 保存、解码校验）和文件添加的默认几何：按原始比例、长边不超过 480px、最小 40px、放在当前页中心，并自动选中。
- 剪贴板里有多张图片时全部添加，依次错开 24px，保留最后一张为选中状态。
- 剪贴板没有图片时完全不拦截粘贴，不影响文本输入和浏览器默认行为；图片无法解码时提示错误，不留下空白图片元素。
- 粘贴始终新建图片元素，不替换当前选中的图片；替换仍走属性面板的“替换图片”或文件选择流程。
- 把剪贴板读取与事件安装拆成独立模块 `js/clipboard-image.js`：只负责从 `ClipboardEvent` 提取图片、按条件安装 `paste` 监听并回调，不依赖图片模型或页面结构，方便以后给背景或其他功能复用。
- 提取文件选择和粘贴共用的自由图片插入逻辑，避免两套添加流程；文件选择与替换行为保持不变。
- 在“添加图片”按钮的悬浮提示中说明也可以 `Ctrl + V`，并在粘贴完成后给出轻量提示。

第一版明确不做：粘贴到背景层、拖放外部图片、解析只存在于 HTML 剪贴板内容里的 `<img>`、剪贴板历史、跨页批量粘贴、粘贴替换选中图片。

## Capabilities

### New Capabilities

（无）

### Modified Capabilities

- `page-editor`: 自由图片增加“从剪贴板粘贴添加”的入口，并定义焦点守卫、非图片内容、多张图片、解码失败和选中行为。

## Impact

- 代码：新增 `js/clipboard-image.js`（剪贴板图片提取与监听安装）；`js/app.js`（粘贴接线、多图插入、与文件选择共用的插入流程）；`index.html`（经典 `<script>` 引入新模块）；`js/ui.js` 或工具条模板（“添加图片”的提示文案）。
- 数据：不新增项目 JSON 字段；粘贴图片沿用现有图片资产，保存/加载/导出自动生效。
- 依赖：无新增运行时依赖，仍是零构建、`file://` 可打开的静态页面。
- 规范：`openspec/specs/page-editor/spec.md` 将被更新。
- 文档：同步 `docs/歌单生成器需求.md` 的图片导入说明。
