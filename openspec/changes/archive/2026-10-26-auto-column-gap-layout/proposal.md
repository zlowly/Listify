# Proposal

## Why

自动列宽当前把表格宽度按 `(a_i - MIN_COL_WIDTH)` 的比例分给各列（`js/layout.js` 的 `fitWidths`）。排序是虚拟字数升序，默认填充是列优先，最后一列往往最长；比例分配又让最长的最后一列拿走最多剩余宽度。默认左对齐时，这些余量以“列内空白”的形式堆在最后一列右侧，形成一条明显的空白带。

用户已确认：剩余宽度应变成列与列之间的等距间隙，而不是各列内部的空白；手动拖动保持现状。

## What Changes

- 自动列宽改为“实测内容宽 + 等距间隙”：
  - `a_i` = 该列最长歌名的 `measureText` 实测宽 + 左右 padding + 安全余量；
  - `g = (W - Σa_i) / (n - 1)`；
  - 前 `n-1` 列 `cell = a_i + g`，最后一列 `cell = a_n`；
  - 最后一列的渲染盒右边缘贴齐表格右边缘。
- `g` 作为内容盒之外的独立间距；对齐/两端对齐只在 `a_i` 内进行，不把 `g` 并入对齐盒。
- `Σa_i > W` 时 `g = 0`，退回现有 `fitWidths` 比例压缩，保留红格溢出警告。
- 单列直接使用表格宽度，不计算 `g`。
- v1 不对极端 `g` 设上限。
- 手动拖动保持现状：拖动时冻结当前渲染列宽（含自动间距）并转为固定列宽；自动间距规则不再生效。
- 更新 `docs/歌单生成器需求.md` 第 43 行的列宽规则。
- 增加 `devChecks` 覆盖等距间隙、最后一列贴右、单列和负间隙 fallback。

第一版不做：列间距封顶、按列间距做拖拽吸附、导出格式变化、排序/填充/动态行/自动续表规则变化。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `category-layout`: 自动列宽从“按比例分配剩余宽度”改为“实测内容宽 + 等距列间距”，并明确对齐/溢出/手动拖动的交互。

## Impact

- `js/layout.js`: 新增自动列宽函数；`assignTableSongs` 保存 `contentWidth`；`devChecks` 增加断言。
- `js/render.js`: 对齐、两端对齐、裁剪和溢出检测使用 `contentWidth`；红格只覆盖内容盒。
- `js/app.js`: 手动拖动继续使用渲染列宽快照；块宽度缩放逻辑不变。
- `docs/歌单生成器需求.md`: 第 43 行规则同步。
- 不引入构建、依赖或运行时网络；仍是 `file://` 可打开的静态页面。
