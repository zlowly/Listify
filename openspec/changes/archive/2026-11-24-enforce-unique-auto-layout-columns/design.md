# Design

## Context

- 自动布局入口在分类块属性面板的「表格」组，确认后调用 `L.app.autoLayoutCategory`，最终由 `L.layout.arrangeTables(element, category, options)` 生成新的 `element.tables`。结果进入撤销栈，参数不写入项目文件。
- 当前 `arrangeTables` 把上一张表的 `columns` 直接作为下一张表的列数上限，因此下一张表可以取到与上一张相同的列数；末表同样复用了相同的上限。实测重复结果：20 首/3 表 `8, 8, 4`，18 首/2 表 `6, 6`，100 首/5 表 `8, 8, 8, 8, 6`。
- 单表列数上限为 `ARRANGE_MAX_COLUMNS = 8`，面板允许请求 1–20 张表，因此请求数量可能天然大于可行唯一列数。
- 纯逻辑回归可直接覆盖 `arrangeTables` 与 `estimateTableCount`；UI 提示只做参数读取与结果展示。

## Goals / Non-Goals

**Goals:**

- 自动布局生成的表格列数两两不同，且自上而下严格递减。
- 请求的表格数作为上限；唯一性约束不可满足时自动取最大可行表格数并明确提示。
- 默认表格数估算不会请求必然重复列数的数量。
- 用已复现的重复列数场景建立回归。

**Non-Goals:**

- 不改变手工增删表格、手工修改列数的行为，不强制手工表格列数唯一。
- 不改变字体、对齐、表格边距、填充顺序或项目文件格式。
- 不引入新的分页/整页自动排版能力。
- 不尝试在默认估算中精确模拟每个表格的宽度可行性；实际布局时的减少与提示仍是兜底。

## Decisions

1. **严格递减：下一张表的列数上限取上一张列数减 1**
   `arrangeTables` 在每张表成功后把 `previousColumns` 设为 `band.columns - 1`，并把该值传给后续 `chooseBand` / `bandColumns`。这样后续表不可能再取到同列数，且天然保持自上而下递减。
   - 备选：生成结果后再检测重复并局部调整。否决：局部调整可能破坏分段容量与列宽约束，且难以保证所有歌名仍完整保留。

2. **表格数从大到小重试，首次成功即采用**
   先计算 `maxAttempt = min(请求表格数, 单表最大列数, 歌名数)`。从 `maxAttempt` 递减到 1，逐个尝试完整切分；唯一性约束或宽度使某数量无法完成时，尝试更少的表格数。首次成功的结果即为最终结果。
   - 备选一：直接拒绝并保留原表格。否决：用户已选择“自动减少表格数并提示”。
   - 备选二：固定预留 `N, N-1, …, 1` 的列数再分配歌名。否决：预留的高列数在窄块中可能不可行，仍需重试，且会过度拉高行数。
   - 单表尝试总能成功（只要每首歌单独放得下），因此重试一定能在 1 张表处收敛；只有单表也无法排版时才返回 `null`。

3. **结果携带请求数量、实际数量与减少标记**
   成功结果增加 `requestedTableCount`（用户输入的最大表格数）与 `tableCountReduced`（实际少于输入值）。`tableCount` 继续表示实际表格数，保持现有调用方兼容。结果只存在于运行时，不进入序列化白名单。
   - 备选：只返回实际数量由 UI 比较输入值。否决：重试发生在布局层，布局层最清楚是否因唯一性约束减少，UI 不需要重复推断。

4. **最终不变量校验**
   尝试完成后检查所有 `table.columns` 是否互不相同且严格递减；校验失败视为本次尝试失败并继续减少表格数。作为防止后续改动的防御，而不是主要机制。

5. **默认估算受唯一列数上限约束**
   `estimateTableCount` 在现有四分位距与跨度估算后，把结果夹在 `1..min(歌名数, ARRANGE_MAX_COLUMNS)`。面板默认值因此不会超过 8 张，也不会超过歌名数。宽度可行性仍由 `arrangeTables` 的减少机制兜底。
   - 备选：让估算读取分类块宽度并模拟切分。否决：估算在面板侧只拿到歌名，引入宽度参数会扩大接口；默认值偏大时布局层已能收敛并提示。

6. **参数更名「最大表格数」，独占一行并让按钮随后**
   标签从「表格数」改为「最大表格数」，与“上限而非硬性数量”的语义一致。更长的标签在 300px 检查栏下无法与「最多行数」并排，因此两个参数改为上下两行；第二行用 flex 容器放置「最大表格数」字段与「自动布局」按钮，按钮随后。300px 与 320px 检查栏实测按钮均能同排：内容区约 253–273px，字段约 150–181px、按钮含帮助图标约 84px。更窄时 `flex-wrap: wrap` 让按钮整组换到下一行，不挤压输入。
   - 备选：保持两个参数同行。否决：`最大表格数` + 输入 + 单位需要约 150px，与「最多行数」同行会把输入压到不可读或溢出。

7. **提示合成，不吞掉超预算信息**
   属性面板把“最大表格数减少”和“超过行数预算”视为两条可同时成立的信息：构造消息片段后一次 `ui.toast` 展示，例如“已自动布局为 4 张表格；为保证各表列数唯一，已从输入的最大表格数 6 张减少；已按实际 32 行排版，超过可用的 28 行。”帮助提示同步说明“各表列数互不相同且严格递减”。

## Risks / Trade-offs

- [请求数量不再被严格满足] → 仅在唯一列数或宽度不可行时减少，并明确提示实际数量与原因；结果可撤销。
- [严格递减可能增加总行数] → 列数不能重复会跳过部分列数组合，短歌名段可能少一列；超过行数预算时沿用现有提示，本变更不静默截断歌名。
- [重试的额外计算] → 歌名只测量一次，宽度数组复用；重试上限为 8 次（默认最大列数），且仅在手动自动布局时发生。
- [默认估算仍非宽度感知] → 默认值只保证不请求超过唯一列数的数量；窄块导致的进一步减少由布局层提示，避免在面板复制布局算法。
- [手工表格仍可重复列数] → 本变更只约束自动布局输出；手工编辑不在范围内，避免改变既有编辑语义。
