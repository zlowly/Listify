# Spec Delta

## MODIFIED Requirements

### Requirement: 动态行限制
只有最后一个表格 SHALL 允许行数为 0；在动态表下方新增表格时，系统 SHALL 先把原动态表冻结为当前行数，再新增动态表；固定表装满且没有下表时，系统 SHALL 自动追加一个复制上一表属性、行数为 0 的新表；该自动续表 SHALL 在使固定末表容量不足的结构编辑动作（把行数改为固定值、修改列数等）发生时同步完成，MUST NOT 仅作为渲染副作用延迟发生。

#### Scenario: 动态表下方加表
- **WHEN** 用户在一个动态表下方新增表格
- **THEN** 原动态表变为固定行数，新表成为动态表

#### Scenario: 固定表装满
- **WHEN** 最后一个固定表已装满且还有剩余歌名
- **THEN** 系统自动在下方创建一个行数为 0 的新表并继续填充

#### Scenario: 行数改固定后同步续表
- **WHEN** 用户把行数为 0 的末表行数改为固定值，且歌名超出全部表格的总容量
- **THEN** 编辑动作完成时系统已自动在末表下方创建行数为 0 的新表，画布与属性栏立即显示该新表，无需重新点击分类块

#### Scenario: 改列数后同步续表
- **WHEN** 用户减少末表列数，使全部表格的总容量小于歌名总数
- **THEN** 编辑动作完成时系统已自动续表，画布与属性栏立即一致

### Requirement: 表格结构变更
用户 SHALL 能在分类块属性中增删表格、修改列数、行数、填充顺序和对齐方式；修改行数后 SHALL 从第一个表开始重新分配歌名；空固定表 SHALL 保留；空动态末表导出时 SHALL 显示为 0 行，编辑时 SHALL 显示 1 行占位行（见“空动态末表占位行”需求）。删除末表且该表承载歌名（剩余表格总容量小于歌名总数）时，上一个表格的行数 SHALL 自动变为 0 以容纳被删表格的歌名；删除未承载歌名的末表时上一个表格 SHALL 保持原固定行数。任何表格结构变更（表格数量变化）后，属性栏的表格列表 SHALL 立即与画布显示一致，MUST NOT 需要重新点击画布上的子分区才同步。

#### Scenario: 增加行数
- **WHEN** 用户把第一个表从 2 行改为 3 行
- **THEN** 后续表格的歌名按新容量重新分配

#### Scenario: 删空固定表
- **WHEN** 用户删除一个没有歌名的固定表
- **THEN** 该表从分类块中移除

#### Scenario: 空动态末表导出
- **WHEN** 存在空的动态末表且用户导出 PNG
- **THEN** 导出图片中该表按 0 行渲染，不出现占位行

#### Scenario: 删除承载歌名的末表
- **WHEN** 用户删除行数为 0 的末表，且该表在页面上承载歌名
- **THEN** 上一个表格的行数自动变为 0，被删表格的歌名流入该表，页面表格数减少一张，属性栏立即与画布一致

#### Scenario: 删除空的末表
- **WHEN** 用户删除行数为 0 且没有歌名的末表
- **THEN** 该表从分类块中移除，上一个表格保持原固定行数不变

#### Scenario: 结构变更后属性栏立即同步
- **WHEN** 用户修改行数、列数或删除表格导致表格数量变化
- **THEN** 属性栏立即显示与画布相同数量的表格（含表格个数提示），无需点击画布上的子分区
