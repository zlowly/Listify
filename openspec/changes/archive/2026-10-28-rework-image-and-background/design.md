# Design

## Context

当前实现把“图片”分成两套模型：

- 自由图片：`js/model.js` 的 `createImageElement` 保存 `fit`（cover / contain / stretch）和 `opacity`；`js/render.js` 的 `drawImageFit` 按 `fit` 在元素矩形内裁切、留白或拉伸；`js/app.js` 的 `handlePoints` 给图片 8 个手柄，`resizeDrag` 直接按屏幕轴修改宽高；`hitTest` 和 `pageOverflow` 都按未旋转矩形计算。
- 背景：`page.background` 是一个独立对象，`render.backgroundGeometry` 按四种尺寸模式计算；`js/io.js` 逐页保存；新页“沿用上页背景”在 `js/app.js` 里调用 `model.createBackground(current.background)`，是一次性深拷贝，所以之后不再同步。

详见 `proposal.md`。行为契约见本变更的 `specs/page-editor/spec.md`、`specs/background-layer/spec.md`、`specs/project-persistence/spec.md`。

## Goals / Non-Goals

**Goals:**

- 自由图片退化成一个“可旋转矩形 + 整张图”，不引入裁剪模式或源裁剪矩形。
- 用一条锚点公式统一八个手柄、等比锁定和任意旋转下的缩放。
- 背景保持现有属性和四种尺寸模式，只把“沿用”从复制改成实时引用。
- 旧项目可加载，版本号升到 2。

**Non-Goals:**

- 不做裁剪、蒙版、滤镜链、旋转手柄、多选变换。
- 不做自由图片的“仅横向/仅纵向”三态缩放；只有等比复选框。
- 不把背景层改成普通内容元素，不引入通用图层系统。
- 不做文字旋转。

## Decisions

### 1. 图片元素：去掉 `fit`，增加 `keepRatio` / `rotation` / `blur`

`js/model.js` 的 `createImageElement` 返回：

```js
{
  id, type: 'image',
  x, y, width, height,
  assetId,
  keepRatio: true,
  rotation: 0,      // 度，绕元素中心
  opacity: 1,
  blur: 0           // 页面像素
}
```

- 图片内容始终铺满 `width × height`，不再有 cover/contain 的裁切或留白。元素矩形就是整张图的可见范围。
- `keepRatio` 只约束编辑交互，不改变渲染：开启时任何手柄都保持元素当前比例（正常情况下等于图片原始比例）；关闭时角手柄可自由拉伸，左右/上下边手柄只改单轴。
- 旋转角度用有限数值保存，渲染时按 `rotation * Math.PI / 180` 使用；属性面板把它归一到 `(-180, 180]`，避免长期累积出无意义的大角度。
- `blur` 单位为页面像素，和背景模糊一致；画布位图本身就是页面尺寸，所以缩放视图和导出时半径一致。

**备选方案**：保留 `fit` 并只加旋转。被否决，因为旋转会与裁切窗口组合出旋转裁切框、源矩形和锚点三套坐标，正是要避免的复杂度。

### 2. 绘制：旋转矩形内先裁剪，再模糊，再绘制

`drawFreeImage` 改为：

```js
ctx.save();
ctx.translate(element.x + element.width / 2, element.y + element.height / 2);
ctx.rotate(rotationRad);
ctx.beginPath();
ctx.rect(-w / 2, -h / 2, w, h);
ctx.clip();
ctx.globalAlpha = clamp(opacity, 0, 1);
if (blur > 0) ctx.filter = 'blur(' + blur + 'px)';
ctx.drawImage(img, -w / 2, -h / 2, w, h);
ctx.restore();
```

- 先裁剪后模糊，模糊在元素边缘被硬切，和现有背景行为一致；不额外引入“模糊溢出边框”的选项。
- 导出复用 `render.drawPage` 和页面裁剪，旋转、模糊、透明度自动包含，不需要单独的导出分支。

### 3. 命中测试与选择框：使用旋转后的四边形

- 命中测试把指针逆旋转到元素本地坐标：`local = R(-θ) · (point - center)`，再判断 `|local.x| <= w/2 && |local.y| <= h/2`。不使用外接矩形，否则斜放图片四角的空白也会被选中。
- 选择框和 8 个手柄绘制在旋转后的矩形上；`handleAt` 同样逆变换后判断。光标方向第一版沿用现有的 8 种方向光标，不随角度旋转（纯视觉细节，不影响操作）。
- `elementBounds` 继续返回未旋转矩形，供分类块、文字和图层使用；新增图片专用的 `elementCorners` / `elementAabb`，溢出警告和选择框使用旋转后的四角。

### 4. 缩放：本地增量 + 页面空间锚点

任意角度下，拖动一个手柄时按以下步骤计算：

```js
// 手指位移转到元素本地坐标
dLocal = R(-θ) · (pointer - pointerStart)

// 先按手柄方向得到新宽高（等比时由一个维度推导）
// 再以拖动手柄的对侧为锚点：
A0 = (sx * w0 / 2, sy * h0 / 2)          // sx, sy ∈ {-1, 0, 1}
P  = C0 + R(θ) · A0                       // 锚点在页面中的位置，拖动前算好
A1 = (sx * w / 2,  sy * h / 2)
C1 = P - R(θ) · A1
x = C1.x - w / 2
y = C1.y - h / 2
```

- 角手柄：`sx`、`sy` 都是 `±1`；边手柄：一个为 `0`。这一条公式同时覆盖旋转、等比和不等比。
- 等比时角手柄取拖拽向量在元素对角线上的投影作为缩放系数；边手柄改一个维度，另一个维度由图片比例推导。对侧边中点作为锚点时，垂直方向的尺寸变化是对称的，锚点不会漂移。
- 最小宽高保持 40px；夹紧后重新套用锚点公式，保证手柄不会越过对侧。
- 开启等比或替换图片时立即归一：保持中心与宽度，高度改为 `width / imageRatio`；图片未加载时暂不归一，加载完成后再处理。关闭等比不改变当前矩形。

**备选方案**：把旋转后的缩放拆成“先旋转到 0、缩放、再转回”。数学等价，但会引入临时状态和多次坐标变换；直接用锚点公式更短，也更容易写成一个纯函数验证。

### 5. 溢出：按四个角判断

`pageOverflow` 对图片取旋转后的四个角，只要任一角在页面外就报警。这比外接矩形准确，也不会因为元素斜放而漏报。分类块和文字仍使用原矩形。导出继续按页面边界裁剪。

### 6. 背景引用：运行时共享对象，JSON 只记录所有者

数据模型：

```js
page.background     // 所有者：背景对象；引用页：与所有者相同的对象引用
page.backgroundRef  // 引用页：所有者页面 id；所有者：null
```

- 运行时引用页直接持有所有者的 `background` 对象，所以现有读取 `page.background` 的渲染、属性面板和导出代码不需要整体改写；修改任意引用页就是修改同一个对象。
- 新建页面：
  - “空白背景”：`background = createBackground()`，`backgroundRef = null`。
  - “引用上页背景”：找到当前页背景的所有者，`backgroundRef = owner.id`，`background = owner.background`。如果当前页本身就是引用页，则指向它的所有者，避免形成链。
- “断开引用”：`background = clone(page.background)`，`backgroundRef = null`，成为新的所有者。
- 删除页面：删除前，把所有 `backgroundRef === deleted.id` 的页面物化为独立副本（克隆 `deleted.background`，清空引用），再删除页面。被删除页如果是引用页，直接删除，不会有人引用它。
- 背景面板：引用页显示“引用第 N 页背景”，并提供“断开引用”；所有者被引用时显示“被 N 页引用”。所有控件照常可编辑，提示文案明确“修改会同步”。
- 新页对话框的“沿用上页背景”改为“引用上页背景”，提示改为共享语义。

**备选方案**：

- 仅共享内存对象、不做持久化：保存后引用关系丢失，不可接受。
- 背景独立成 `project.backgrounds` 集合、页面存 `backgroundId`：结构更干净，但要改所有 `page.background` 访问点和背景资产去重逻辑，超出本次范围。
- 写时复制（编辑引用页自动断开）：能保留独立性，但“改了就悄悄不同步”和“任何时候都一致”的预期冲突，还会多出 linked/detached 隐式状态。被否决。

### 7. 持久化：版本 2，JSON 只由所有者写背景

`js/io.js`：

- `version: 2`。加载时接受 1 和 2，拒绝大于 2 或其它值。
- 保存：所有者页写 `background` 和 `backgroundRef: null`；引用页写 `backgroundRef: ownerId`，不写 `background`（或写 `null`）。
- 加载：先解析所有页面，再解析引用。`backgroundRef` 必须指向存在的页面；如果目标页本身也是引用，继续解析到最终所有者，带访问集合检测环；解析失败按项目损坏处理，保留当前项目。
- 图片元素：保存 `keepRatio`、`rotation`、`blur`，不再保存 `fit`。加载 v2 时缺省字段按 `true` / `0` / `0` 处理；字段存在但类型或范围非法时报错。
- v1 迁移：
  - `stretch` → 矩形不变，`keepRatio: false`。
  - `contain` → 元素矩形改为原矩形内完整容纳图片的比例矩形（居中），`keepRatio: true`。
  - `cover` → 元素矩形改为以原矩形中心为中心、按图片比例覆盖原矩形的矩形，`keepRatio: true`。原 `cover` 被裁掉的部分会重新露出，无法完全还原；这是去掉填充模式的已知代价。
  - `rotation: 0`、`blur: 0`。
  - v1 的所有页面都是背景所有者，`backgroundRef: null`。
- `project.version` 升到 2 后，旧版本应用无法加载新文件；本项目是本地工具，不做向下兼容输出。

**备选方案**：保留 `fit` 字段做兼容渲染。被否决：代码里会长期存在两套图片渲染路径，违背本次简化的目的。

### 8. UI 与文档

- 自由图片属性：当前图片、替换、位置 X/Y、宽度/高度、`缩放时保持比例` 复选框、透明度、模糊、旋转角度；删除“填充”组。
- 背景属性：保留现有控件；引用页增加引用提示和“断开引用”按钮；新页对话框文案改为“引用上页背景”。
- 图层面板的图片副标题不再显示 `fit`，可显示旋转角度或“图片”；背景行显示“引用 · 第 N 页”或当前尺寸模式。
- `docs/歌单生成器需求.md` 同步：自由图片不再有填充模式，改为铺满矩形 + 等比 + 旋转 + 模糊；背景创建改为引用。

## Risks / Trade-offs

- **v1 的 cover 无法完全还原** → 迁移时选择“不裁切、按比例覆盖原矩形”，并在 change 说明中标注；用户可手动调整宽高。若旧项目很多，再考虑加一次性的“保留旧渲染”分支，但本次不做。
- **旋转 + 缩放的锚点算错** → 把锚点公式写成纯函数，用 0°/30°/90°/180° 和四个角做手工断言；所有手柄共用同一条路径。
- **编辑引用页会改到所有页** → 面板显著提示引用关系，并提供“断开引用”；这是“任何时候都一致”的直接代价。
- **删除所有者后引用组解散** → 物化为独立副本，画面不变；后续修改不再同步，接受这个降级。
- **旋转图片的溢出警告变多** → 按四角判断是准确行为；斜放接近页边时报警是预期结果，不额外放宽。
- **模糊在元素边缘硬切** → 与背景一致；如果以后要柔和边缘，需要另立需求，不在本次混入。
- **命中测试与选择框不一致** → 两者都使用同一套旋转四边形和同一个角度，避免一个用 AABB、一个用四边形。

## Migration Plan

1. 先改 `js/model.js` 的默认值、背景所有者解析和旧 `fit` 迁移辅助。
2. 改 `js/render.js` 的绘制、命中、溢出；用固定角度手工核对。
3. 改 `js/app.js` 的手柄、缩放、背景引用创建/断开/删除物化。
4. 改 `js/ui.js` 的属性面板、图层面板、新页对话框和提示文案。
5. 改 `js/io.js` 的版本 2 读写、引用解析和 v1 迁移。
6. 用一份 v1 项目做加载、保存、再加载的往返；用新项目验证旋转、等比、模糊、背景同步和导出。
7. 更新 `docs/歌单生成器需求.md`，运行 `openspec validate rework-image-and-background --strict`。

回滚策略：变更只影响本地 JSON 和静态代码；如需回滚，恢复代码并加载变更前的 v1 项目。已经保存的 v2 文件不会被旧代码读取，这是版本升级的预期代价。

## Open Questions

- 以后是否需要在画布上提供旋转手柄；当前只有数值输入，属于可延后的交互增强，不影响数据模型。
- 新页对话框是否还需要“复制上页背景（独立副本）”选项；当前用“引用后断开”覆盖该需求，暂不增加第三种入口。
