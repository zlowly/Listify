# Spec Delta

## MODIFIED Requirements

### Requirement: 导入项目
系统 SHALL 允许用户选择项目 JSON 并恢复页面、元素、歌单、图片、每页背景和全局背景来源页；在替换当前项目之前 SHALL 要求确认；导入前 SHALL 校验版本和基本结构；版本 1–4 SHALL 自动迁移到版本 5；版本 4 的 `background.images` SHALL 映射为 `kind: 'image'` 的 `background.items`；校验失败 SHALL 报错并保留当前项目和当前草稿不变；导入成功后 SHALL 用导入项目替换当前草稿。

#### Scenario: 导入前确认
- **WHEN** 用户选择了有效的项目文件
- **THEN** 系统先确认是否用该项目替换当前草稿，确认后才执行替换

#### Scenario: 加载有效项目
- **WHEN** 用户选择由本应用保存的版本 5 JSON
- **THEN** 页面、版面、每页背景、背景图形、全局来源页和歌单恢复，可继续编辑

#### Scenario: 加载版本 4 项目
- **WHEN** 用户导入版本 4 项目
- **THEN** 每页背景的 `images` 数组按原顺序转换为 `items` 中的图片条目，项目以版本 5 继续编辑

#### Scenario: 加载版本 3 项目
- **WHEN** 用户导入版本 3 项目
- **THEN** 每页 `backgroundId` 对应的背景展开为该页自己的背景副本，图片资产共享，图片按 items 保存

#### Scenario: 版本 3 的全局背景迁移
- **WHEN** 版本 3 项目开启全局背景，且第 2 页使用该背景
- **THEN** 导入后第 2 页成为全局来源页，各页保留自己的背景副本，取消全局后恢复各自背景

#### Scenario: 版本 3 全局背景没有页面引用
- **WHEN** 版本 3 项目开启全局背景，但没有任何页面的 `backgroundId` 指向该背景
- **THEN** 导入时把该背景复制到第一页并令其成为全局来源页，保证画面不变

#### Scenario: 加载版本 2 项目
- **WHEN** 用户导入版本 2 项目
- **THEN** 系统把引用组折叠为每页自己的背景副本，画面与导入前一致

#### Scenario: 加载版本 1 项目
- **WHEN** 用户导入版本 1 项目
- **THEN** 系统按迁移规则转换图片填充模式，并为每页建立独立背景，项目可继续编辑

#### Scenario: 全局来源页无效
- **WHEN** 文件中的 `globalBackgroundPageId` 指向不存在的页面
- **THEN** 校验失败并报错，不替换当前项目

#### Scenario: 加载损坏 JSON
- **WHEN** 文件不是合法 JSON 或缺少必要字段
- **THEN** 系统报错，当前项目和当前草稿都不被替换

#### Scenario: 导入后刷新
- **WHEN** 用户成功导入项目后刷新页面
- **THEN** 恢复的是刚导入的项目，而不是导入前的草稿

### Requirement: 草稿自动保存
系统 SHALL 在当前工作区发生编辑后自动保存草稿；草稿 MUST 包含页面、元素、歌单、每页背景、背景图形、全局背景来源页、图片资产和当前页；用户 MUST NOT 需要手动保存。

#### Scenario: 编辑后刷新
- **WHEN** 用户导入歌单、添加页面并调整版面后刷新
- **THEN** 页面、元素、歌单、每页背景和当前页恢复

#### Scenario: 图片资产保留
- **WHEN** 项目使用了背景图或自由图片后刷新
- **THEN** 图片仍能显示，不依赖原始文件路径

#### Scenario: 未放置分类保留
- **WHEN** 歌单中存在未放置到页面的分类后刷新
- **THEN** 该分类仍出现在左侧未放置列表

#### Scenario: 立即刷新
- **WHEN** 用户完成一次编辑后立即刷新或关闭页面
- **THEN** 最近一次编辑仍被保存

#### Scenario: 旧草稿迁移
- **WHEN** 浏览器中存在版本 1–4 项目结构的旧草稿
- **THEN** 草稿按对应版本迁移到版本 5 后恢复，不报版本不支持

### Requirement: 项目版本
项目 JSON SHALL 包含版本号；当前支持版本 SHALL 为 5；版本 1–4 SHALL 自动迁移到 5；系统 SHALL 只接受版本 1、2、3、4、5，其它版本 MUST 拒绝加载并给出明确提示。

#### Scenario: 版本 1 项目
- **WHEN** 用户加载版本号为 1 的项目
- **THEN** 系统完成迁移并以版本 5 继续编辑

#### Scenario: 版本 2 项目
- **WHEN** 用户加载版本号为 2 的项目
- **THEN** 系统完成迁移并以版本 5 继续编辑

#### Scenario: 版本 3 项目
- **WHEN** 用户加载版本号为 3 的项目
- **THEN** 系统完成背景库到每页背景的迁移，并以版本 5 继续编辑

#### Scenario: 版本 4 项目
- **WHEN** 用户加载版本号为 4 的项目
- **THEN** 系统把背景 `images` 转换为 `items`，并以版本 5 继续编辑

#### Scenario: 未来版本
- **WHEN** 用户加载版本号高于 5 的项目
- **THEN** 系统提示版本不支持，不尝试部分加载

#### Scenario: 未知版本
- **WHEN** 用户加载版本号不是 1、2、3、4 或 5 的项目
- **THEN** 系统提示版本不支持，不替换当前项目

### Requirement: 往返一致
保存后重新加载 SHALL 保持页面顺序、全局尺寸和边距、元素坐标与尺寸、子分区样式、表格结构、手动列宽、z-order、图片与图形的旋转角度、等比锁定、透明度、模糊、亮度、色相、渐隐模式与渐隐角度、渐隐位置、转场宽度、顶部/底部透明度、图形形状/内夹角/填充方式/颜色/带符号圆角（含负值内凹）/边框厚度、每页背景的填充色与 `items` 顺序、每个图片条目的定位与自定义矩形、全局背景来源页、歌单原始顺序；未放置分类 SHALL 也被保留。

#### Scenario: 版面往返
- **WHEN** 用户保存含两个页面和未放置分类的项目后重新加载
- **THEN** 两页版面、层级和未放置分类与保存前一致

#### Scenario: 手动列宽往返
- **WHEN** 项目中的表格使用手动列宽
- **THEN** 加载后列宽仍为保存时的像素比例

#### Scenario: 图片变换往返
- **WHEN** 图片设置了 37 度旋转、关闭等比锁定并设置模糊
- **THEN** 加载后旋转、等比状态和模糊值保持不变

#### Scenario: 图片效果往返
- **WHEN** 某张自由图片与某张背景图分别设置了亮度 80%/130%、色相 -45°/60°、双向/单向渐隐、角度 30°/120°，并设置不同的位置、转场宽度与两端透明度
- **THEN** 加载后两张图的全部效果参数都与保存前一致，画面逐像素相同

#### Scenario: 背景引用往返
- **WHEN** 项目包含旧版本的背景引用（v1–v3）并保存为 v5 后重新加载
- **THEN** 每页背景已固化为该页自己的填充色与 items，不保留背景库或跨页引用

#### Scenario: 背景库往返
- **WHEN** 用户保存并重新加载当前项目
- **THEN** 项目不出现背景库、背景名称或页面到背景的引用，每页背景独立保留

#### Scenario: 图形往返
- **WHEN** 一个内容图形为菱形、内夹角 45°、圆角 12、边框厚度 8、边框颜色红色，并设置亮度与单向渐隐
- **THEN** 加载后形状、角度、圆角、边框、颜色、效果参数与保存前一致，画面逐像素相同

#### Scenario: 负圆角往返
- **WHEN** 一个图形使用负圆角 -18 表示内凹
- **THEN** 加载后圆角仍为 -18，内凹缺口与保存前一致

#### Scenario: 每页背景往返
- **WHEN** 第 2、3 页使用不同的填充色、图片和图形并保存
- **THEN** 加载后两页分别恢复自己的背景，修改第 2 页不影响第 3 页

#### Scenario: 背景条目往返
- **WHEN** 某页背景的 items 顺序为图片 A、图形 B、图片 C，且 B 有圆角与渐隐
- **THEN** 加载后 items 顺序、图片定位与图形字段都与保存前一致

#### Scenario: 全局模式往返
- **WHEN** 全局背景开启，第 1 页存有自己的背景
- **THEN** 加载后 `globalBackgroundPageId` 和第 1 页自己的背景都保持不变

### Requirement: 资源缺失处理
项目引用的图片资产缺失或损坏，或背景 `items` 中的图片条目引用不存在的资产，或 `globalBackgroundPageId` 指向不存在的页面时，系统 SHALL 报错并保留当前项目，不得静默加载为空白图片或失效引用；图形条目不引用图片资产，MUST NOT 参与资产缺失检查。

#### Scenario: 资产缺失
- **WHEN** JSON 中某元素引用了不存在的资产 ID
- **THEN** 系统提示项目损坏并停止加载

#### Scenario: 背景图片资产缺失
- **WHEN** JSON 中某个背景图片条目引用不存在的资产 ID
- **THEN** 系统提示项目损坏并停止加载

#### Scenario: 背景引用失效
- **WHEN** 旧项目中的背景引用无法解析到任何页面或背景记录
- **THEN** 系统提示项目损坏并停止加载，不产生指向不存在记录的背景引用

#### Scenario: 背景条目类型无效
- **WHEN** JSON 中某个背景条目的 kind 不是 `image` 或 `shape`，或图片条目缺少 `assetId`
- **THEN** 系统提示项目损坏并停止加载

#### Scenario: 全局背景引用失效
- **WHEN** `globalBackgroundPageId` 指向不存在的页面
- **THEN** 系统提示项目损坏并停止加载

#### Scenario: 图形不参与资产检查
- **WHEN** 项目只包含图形条目且没有任何图片资产
- **THEN** 项目正常加载，不产生资产缺失错误

### Requirement: 旧项目缺少图片效果字段
加载不含亮度、色相、渐隐模式、渐隐角度、渐隐位置、转场宽度或两端透明度的旧项目（版本 1–4）时，系统 SHALL 为每张图片取默认值（亮度 1、色相 0、渐隐关闭、角度 0；位置/宽度/两端透明度按当前渐隐模式的预设）并正常加载，MUST NOT 判为损坏或版本不支持；再次保存后 SHALL 写出显式的效果字段，使新旧文件往返后数据一致。

#### Scenario: 旧项目正常打开
- **WHEN** 用户导入一个版本 4、图片条目中没有任何效果字段的项目
- **THEN** 项目正常加载，所有图片按默认效果绘制，该项目的草稿被正常替换

#### Scenario: 保存后补齐字段
- **WHEN** 用户打开该旧项目后直接导出项目文件
- **THEN** 导出的 JSON 中每张图片都含显式的亮度、色相、渐隐模式、渐隐角度、渐隐位置、转场宽度、顶部透明度与底部透明度字段，数值为该模式下的默认值

#### Scenario: 新文件在旧构建中的表现
- **WHEN** 由本项目导出的版本 5 文件被只支持版本 4 的旧构建打开
- **THEN** 旧构建提示版本不支持，不替换当前项目；当前版本仍可读取版本 4 文件

### Requirement: 导出项目文件
系统 SHALL 把当前项目导出为本地 JSON 文件；文件 MUST 包含版本号、全局页面尺寸、边距、歌单数据、全部页面、内容元素、每页的背景（填充色与有序 `items` 列表，条目为图片或图形）、全局背景来源页 ID、图片资产；图片 SHALL 以 base64 存储；图形 SHALL 保存完整几何（含负圆角）、填充与效果字段；文件 MUST NOT 包含背景库、背景名称、`backgroundId`、`backgroundRef`、`unifiedBackground` 或 `unifiedBackgroundId`。

#### Scenario: 保存后重新打开
- **WHEN** 用户导出项目并关闭页面
- **THEN** 得到的 JSON 包含当前所有页面、每页背景和歌单数据

#### Scenario: 图片内嵌
- **WHEN** 项目使用背景图和自由图片
- **THEN** JSON 中包含对应图片的 base64 数据，不依赖原始文件路径

#### Scenario: 保存每页背景
- **WHEN** 三页使用三种不同的背景
- **THEN** JSON 为每页分别保存填充色与 items 列表，不保存共享背景实体

#### Scenario: 保存图形
- **WHEN** 页面包含内容图形，背景包含图形条目
- **THEN** JSON 保存两种图形的形状、宽高、旋转、填充方式、颜色、带符号圆角（含负值内凹）、边框厚度与全部效果字段

#### Scenario: 保存全局来源页
- **WHEN** 全局背景来源为第 2 页且各页背景不同
- **THEN** JSON 记录 `globalBackgroundPageId` 指向第 2 页，并仍保存每页自己的背景

#### Scenario: 不保存背景库
- **WHEN** 用户导出项目
- **THEN** JSON 中不存在背景库、背景名称、使用页数或页面到背景的引用

### Requirement: 图片资产去重
项目 SHALL 按图片内容标识资产；相同图片字节被内容元素或多个背景使用时 MUST 只保存一份；内容元素和背景图片条目 SHALL 通过资产 ID 引用图片；图形条目不引用图片资产；替换图片 SHALL 产生新资产；删除背景或图片 SHALL 只在没有其它引用时释放资产。

#### Scenario: 两页共用一张图
- **WHEN** 第 1 页和第 2 页使用同一张背景图
- **THEN** JSON 中该图片只出现一次

#### Scenario: 换图产生新资产
- **WHEN** 用户在某页把背景换成另一张图
- **THEN** 新图作为新资产保存，原资产仍可被其它背景或内容引用

#### Scenario: 删除后释放资产
- **WHEN** 用户删除某背景的唯一图片，且没有其它元素或背景引用该资产
- **THEN** 保存的 JSON 不再包含该资产

#### Scenario: 图形不产生资产
- **WHEN** 用户只添加图形而不添加任何图片
- **THEN** 项目资产列表不增加，删除图形也不触发资产释放

### Requirement: 草稿资产以二进制存储

浏览器草稿库中的图片资产 SHALL 以二进制形式（Blob 或 ArrayBuffer）保存；base64 编码 SHALL 只用于项目 JSON 的导入导出交换格式，以及恢复时向 `buildProject` 交接的内存表示。恢复草稿时，MUST 兼容此前以 base64 字符串保存的资产，并 SHALL 在成功恢复后以二进制形式写回。格式升级 MUST NOT 导致旧草稿无法恢复。从草稿库读出的资产数据 SHALL 是纯 base64（不含 `data:` 前缀，可被 `atob` 直接解码）；恢复流程 SHALL 在任何情况下剥除历史记录里可能存在的 data URL 前缀，MUST NOT 因编码前缀把可用草稿判为损坏。

#### Scenario: 草稿体积
- **WHEN** 项目包含多张背景图与自由图片
- **THEN** 草稿库中的图片以二进制保存，存储占用与图片原始字节同量级，不出现 base64 带来的额外膨胀

#### Scenario: 旧草稿恢复
- **WHEN** 用户打开由旧版本保存、资产仍为 base64 的草稿
- **THEN** 页面、歌单与图片完整恢复，后续保存改用二进制存储

#### Scenario: 项目文件格式不变
- **WHEN** 用户导出项目 JSON
- **THEN** 图片仍以 base64 内嵌，草稿二进制存储不改变项目文件交换格式

#### Scenario: 项目文件格式
- **WHEN** 用户导出项目 JSON
- **THEN** 图片仍以 base64 内嵌，项目版本与背景 items 结构使用当前版本 5 格式

#### Scenario: 含图片草稿刷新恢复
- **WHEN** 项目含一张或多张背景图，用户等到“草稿已自动保存”后刷新页面
- **THEN** 草稿正常恢复，页面、背景图与图片资产全部回来，MUST NOT 弹出“草稿无法恢复”

#### Scenario: 资产数据不带 data URL 前缀
- **WHEN** 恢复流程从草稿库读出二进制资产记录
- **THEN** 交给 `buildProject` 的 `asset.data` 是纯 base64，可被 `atob` 直接解码成原始字节

#### Scenario: 历史 data URL 记录仍可恢复
- **WHEN** 草稿库中存在以 `data:image/…;base64,` 形式保存的旧资产记录
- **THEN** 恢复时剥除前缀后正常加载图片，MUST NOT 判为损坏
