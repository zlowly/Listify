# Proposal

## Why

图层视图的图片行缩略图按既有约定只呈现原始资产外观；当用户把某张图片的色相调偏后，行内缩略图与画布实际颜色明显不一致，用户在一页多张同资产（或相似外观）图片时难以靠图层列表辨认身份。色相是调色参数中对"颜色身份"影响最大的一项，值得在缩略图中反映。

## What Changes

- 内容图片行与背景图片子行的缩略图增加色相（`hue`）属性的影响：条目 `hue` 为非零有限值时，缩略图按 `hue-rotate(Ndeg)` 着色；`hue` 为 0、缺失或非法时仍显示原始资产外观。
- 其余效果维持现状：缩略图 MUST NOT 烘焙裁剪、亮度、渐隐、透明度与模糊，行高、内边距、字号、悬停/选中样式不变（**BREAKING**：既有需求"缩略图不反映任何调色效果"收窄为"只反映色相"）。
- 缩略图与画布共用同一份色相归一化与滤镜串格式，避免两处各自换算产生偏差。

## Capabilities

### New Capabilities

- 无：本次只调整既有图层视图图片行缩略图的呈现规则。

### Modified Capabilities

- `editor-shell`：需求「图片行显示资产缩略图」由"呈现原始资产外观、不烘焙任何效果"修改为"额外反映条目的色相属性，不烘焙裁剪、亮度、渐隐、透明度与模糊"。

## Impact

- 代码：`js/render.js` 新增并导出一个色相滤镜小助手（复用既有 `finiteOr` 归一化）；`js/ui.js` 的 `layerThumb` 增加条目参数并输出 `filter` 样式，两个调用点（内容图片行、背景图片子行）传入对应条目；`js/ui-property-panel.js` 的色相输入绑定在写入后补一次 `ui.renderLayerPanel()`，让缩略图随滑块即时刷新。`index.html` 脚本顺序不变，不新增文件。
- 数据读取（只读）：`element.hue` / 背景图片条目的 `hue`；项目 JSON、草稿库、资产库、导出与项目 schema 均不改动。
- 行为差异：色相非 0 的图片行缩略图颜色随画布同步变化；色相为 0 的项目（含旧项目无字段）外观与改动前完全一致。
- 验证：Node 回归套件已装载 `js/render.js`，可对新助手做纯逻辑断言；浏览器手动验证改色相后图层行缩略图同步变化。
