# Design

## Context

页面背景分组由 `js/ui-property-panel.js` 的 `backgroundGroup()` 生成 HTML，`bindBackgroundGroup()` 绑定事件；属性卡片外壳由 `js/ui-fields.js` 的 `propGroup()` 提供，标题右槽 `title-right` 已用于放 `?` 图标，现有 `.pill` 样式可承载徽标。缩略图是 `canvas[data-preview-page]`，由 `js/render.js` 的 `paintBackgroundPreviews()` 按 `clientWidth/clientHeight` 合成，CSS 固定为 72×96。复制背景弹窗复用 `.bg-preview-sm`，不在本次范围。代码无构建步骤，样式由 `style.css` 直接加载。

## Goals / Non-Goals

**Goals:**

- 让页面背景分组像其它属性卡片一样可以纵向扫读：预览、字段、动作各自成列或成行，不折行、不悬空。
- 三态（普通页 / 全局来源页 / 被覆盖页）各自只出现该状态需要的控件和一句原因。
- 规则说明进 `?`，随数据变化的信息留在行内。

**Non-Goals:**

- 不改背景数据模型、全局背景指针、撤销粒度、图片资产去重。
- 不改图层面板的背景行、复制背景弹窗、画布命中与手柄、PNG 导出。
- 不引入新颜色、新圆角档位、新组件库或非 Baseline API（不使用 `aspect-ratio` 依赖布局计算，尺寸由 JS 给出）。

## Decisions

### 1. 预览框尺寸由页面尺寸计算，不用固定 3:4 框

`backgroundGroup()` 读取 `project.pageSize`，按 `contain` 规则算出一个最长边为 96px 的整数宽高，写成内联 `style="width:Wpx;height:Hpx"` 到 canvas 上；`paintBackgroundPreviews()` 继续按 `clientWidth/clientHeight` 合成，无需改绘制逻辑。现有 CSS 固定尺寸删除，`.bg-preview-sm` 保持 40×52 仅供复制弹窗。

- 理由：预览框就是缩略图本身，没有额外留边，缩略图能真实反映纸张比例；极端页面尺寸下 `contain` 仍保持比例，不会把字段列挤没。
- 备选：CSS `aspect-ratio` + `height:96px; width:auto`。收益是少一行 JS，但宽高由浏览器的 replaced-element 规则决定，`canvas.width` 属性与 CSS 尺寸冲突时需要额外覆盖，调试成本更高，故放弃。

### 2. 右侧内容改用既有 `field()` 网格，填充色值常驻

卡片改成两列网格：`auto minmax(0,1fr)`，左列缩略图，右列两个标准字段行：

- `图片`：值文本 `N 张`，0 张时显示 `无图片`（承担“框外标注”，不覆盖填充色）。
- `填充色`：既有 `colorInput()` 色块 + 只读 `#RRGGBB` 文本，点击色块开系统取色器。

标签列沿用主面板 72px。0 张时不再另加占位或虚线框。

- 理由：直接复用 `.field` 的标签/控件节奏，左缘与上方「页面边距」等字段对齐；色值是检查表该有的可校对信息。
- 备选：在缩略图下加「无图片」小字。会多出一行高度且与图片行重复，放弃。

### 3. 动作区用两列等宽网格，按状态换文案

`.bg-actions` 使用 `display:grid; grid-template-columns:1fr 1fr; gap:6px`，按钮 `width:100%`，四枚按钮固定为两行两列。文案：`选择背景`（0 张）/`更换背景`（≥1 张）、`＋ 图片`、`复制背景…`、`清空背景`。0 张时 `清空背景` 加 `disabled`。`清空背景` 保持默认按钮样式（动作可撤销，不是不可逆删除），放在网格末位。

- 理由：四枚按钮宽度不一时 flex 换行不可控；网格把折行变成设计意图。命名与图层面板「添加背景图片」语义对齐，去掉行话「叠图」。
- 备选：单行四枚小按钮。300px 检查栏下实测 280px 需求对 273px 可用宽，必然折行或挤压文字，放弃。

### 4. 张数与全局来源进标题徽标，状态文案降到一句

标题右槽放 `<span class="pill pill-gray">N 张图</span>`（0 张显示 `无图片`）与来源页的 `<span class="pill pill-blue">全局来源</span>`，再接现有 `?`。普通态正文不放状态段；来源态只靠徽标。被覆盖态正文只保留一行 `显示第 N 页的全局背景`（11px 次级墨），不再重复「不显示」「先取消」等三处说明。

- 理由：徽标在分组收起后仍可见，符合既有折叠约定；蓝色只出现在状态徽标里，不写蓝色正文，符合 One Blue Rule。
- 备选：继续用 `.bg-status` 蓝色段落。占用纵向空间且把状态色当成强调色，放弃。

### 5. 被覆盖页只保留只读呈现与两个动作

覆盖态隐藏 `选择/更换背景`、`＋ 图片`、`复制背景…`、`清空背景`、填充色控件与全局勾选行，保留：本页缩略图、一行来源说明、`取消全局背景` 按钮、`本页接管` 勾选（`prop-bg-global` 改为该文案，取消勾选仍走取消全局路径由按钮承担）。

- 理由：四个禁用按钮是同一事实的四份噪音；隐藏后读屏与键盘也不会落到一串不可用控件。原因由唯一一行说明承担。
- 备选：保留禁用按钮只压缩文案。仍然有 0.45 透明度的死控件占两行，放弃。

### 6. 规则进 `?`，数据留行内

分组标题 `?` 文案合并三条不变规则：背景位于内容下方；整套替换会同时替换填充色；勾选后所有页使用本页背景并同步修改。行内不再出现这些句子。

- 理由：沿用「会变的行内、不变的进 `?`」判定；浮层已有 240px 宽与自动翻转，长句可承载。

### 7. 事件与可访问性

`bindBackgroundGroup()` 保留现有 id 与处理逻辑，只改文案与显隐；覆盖态不渲染的控件自然没有绑定目标，绑定函数对缺失节点已做存在性判断或 `bind()` 无节点即跳过。`本页接管` 与 `所有页使用此背景` 共用 `prop-bg-global`，勾选调 `setGlobalBackgroundPage()`，取消调 `clearGlobalBackground()`。动作按钮使用 `type="button"`，`＋ 图片` 补 `aria-label="添加背景图片"`。

## Risks / Trade-offs

- **隐藏禁用控件可能让用户找不到编辑入口** → 覆盖态固定显示一行「显示第 N 页的全局背景」与「取消全局背景」「本页接管」，两个出口都在原位；验证时逐态走查键盘顺序。
- **极端页面尺寸使缩略图过窄或过宽** → `contain` 计算以比例优先，极端页面允许短边小于 48px；字段列最少约 150px；1080×1920、1920×1080、2K 与自定义尺寸都要截图核对。
- **徽标计数在面板重渲染后才更新** → 现有改值路径都会 `renderAll()`/`renderProperties()`，与其它分组一致；不新增局部刷新逻辑。
- **复制弹窗仍用固定 40×52 预览** → 明确不在范围；CSS 选择器限定 `.bg-card .bg-preview`，避免 `.bg-preview` 通用规则泄漏到弹窗。
- **文案改动影响既有测试/文档引用** → 全仓 grep「叠图」「所有页显示本页背景」；归档变更不改写，只更新主 spec 与运行界面。

## Migration Plan

纯前端界面改动，无数据迁移。回滚只需还原 `js/ui-property-panel.js` 与 `style.css` 两个文件；项目 JSON、草稿与导出结果不受影响。
