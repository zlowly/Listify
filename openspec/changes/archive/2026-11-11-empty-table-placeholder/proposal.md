# Proposal

## Why

在分类块歌名子分区点「＋ 添加表格」后，新表是动态表（行数 0），在歌名流入之前按 0 行渲染、高度为 0，画布上看不到任何变化；用户必须先手动调小上一表行数、等歌名流入新表才能确认新表存在，交互不直观。

## What Changes

- 编辑态下，空的动态末表（末表 + 行数 0 + 0 首歌名）显示 1 行占位行：
  - 占位行底色用与溢出警告相同的 `#fee2e2` 红色；
  - 行内居中绘制浅灰小标签「空」，与"歌名超宽"警告消歧，避免用户误以为是列宽问题而去拖列宽；
  - 占位行遵守该表的 x 位置、宽度、边距与列数（列分隔线照常绘制），手动列宽模式同样适用；
  - 占位行在编辑态布局中占 1 行高度（块在编辑器内变高一行）；第一首歌名流入后占位行自动消失，由真实行替代。
- 导出 PNG 时空动态末表仍按 0 行渲染，占位行 MUST NOT 出现（归入"编辑辅助不导出"原则）。
- 编辑态的页面溢出判定（"⚠ N 个元素超出页面"标记）计入占位行高度，所见即所得；警告随歌名流入自然消失。
- 编辑态点击占位行区域可选中该分类块（命中测试与布局一致）。
- 范围限定：仅作用于"末表 + 行数 0 + 0 首歌"状态；空固定表已显示完整网格、中间表不允许行数 0，均不受影响。
- 占位行是渲染/布局派生值，不写入项目数据，保存/加载格式不变。

## Capabilities

### New Capabilities

（无）

### Modified Capabilities

- `category-layout`：空动态末表的行为变更——编辑态显示 1 行占位行（红底 `#fee2e2` + 「空」标签，占 1 行布局高度），导出态仍为 0 行；"表格结构变更"需求相应修改，"编辑辅助不导出"清单加入占位行。

## Impact

- `js/layout.js`：`layoutCategory`/`assignTableSongs` 增加编辑态分支（空动态末表按 1 行计高，cells 仍为空）；`_layout` 缓存需区分编辑态/导出态。
- `js/render.js`：`drawCategory` 在 editMode 下绘制占位行（红底 + 「空」标签 + 列分隔线）。
- `js/app.js`：命中测试、页面溢出标记沿用 `layoutCategory` 结果，需统一使用编辑态布局，无新逻辑。
- `js/export.js`：无改动（`editMode: false` 自然得到 0 行）。
- 无新增依赖；零构建约束不变；保存/加载格式不变。
