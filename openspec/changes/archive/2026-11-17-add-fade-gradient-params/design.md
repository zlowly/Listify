# Design

## Context

现有渐隐在 `js/model.js` 里用 `fadeGradientPoints(angle, width, height)` 给出「沿角度轴铺满图片投影」的两个端点，`js/render.js` 的 `fillFadeMask` 用 `createLinearGradient` + `destination-in` 把渐变乘进位图 alpha。单向是 `1 → 0` 两个色标，双向是 `0 → 1 → 0` 三个色标。因此新增「起点、坡长、两端透明度」只是把固定几何变成参数化色标，不需要新的合成方式。

坐标沿用现有约定：角度 0° 自上而下、顺时针递增；渐变轴相对图片自身矩形，图片旋转时掩膜随位图一起旋转。轴向参数 `t ∈ [0,1]` 以图片在该方向上的投影长度为单位，0 是角度轴的起始边（0° 时是图片顶边）。

## Goals / Non-Goals

**Goals:**

- 五个参数全部参与渲染，单向与 Kdenlive Alpha Gradient 的语义一致。
- 双向的位置可移动中部的清晰带，上下坡可以不等长。
- 默认值精确复现旧观感：旧单向仍是不透明→透明铺满整图，旧双向仍是中点为尖峰的两端淡出。
- 新增字段保持可选、版本仍为 3；画布、草稿、项目文件、完整页面导出共用同一套几何。

**Non-Goals:**

- 不实现 Kdenlive 的 Operation（Write on clear / Add / Min / Max / Subtract）。
- 不做渐变色调、背景填充色渐变、逐像素抖动。
- 不改变图片几何、命中测试、层级、背景裁剪与导出尺寸。

## Decisions

### 1. 数据模型与默认值

新增扁平字段（与 `brightness` / `fadeAngle` 同级，便于逐字段序列化）：

| 字段 | 含义 | 范围 | 单向预设 | 双向预设 |
| --- | --- | --- | --- | --- |
| `fadePosition` | 单向：渐变起点；双向：不透明带中心 | 0–1 | 0 | 0.5 |
| `fadeWidth` | 单向：坡长；双向：不透明带宽度 | 0–1 | 1 | 0 |
| `fadeTop` | 起点端透明度（1 = 全透明） | 0–1 | 0 | 1 |
| `fadeBottom` | 终点端透明度 | 0–1 | 1 | 1 |
| `fadeAngle` | 已存在 | 0–360 | 0 | 0 |

模式预设集中在 `FADE_MODE_DEFAULTS`，`fadeDefaults(mode)` 返回副本，`fadeValues(item)` 负责「缺字段按当前模式补齐 + 夹取范围」。schema、面板、渲染都只调用这两个函数，避免三处各写一份默认值。

为什么存储 0–1 而不是 0–100：与 `opacity` 一致，渲染和夹取不需要反复除 100；面板统一用 `percentLabel` 显示百分比。

### 2. 单向几何

设轴长为 `L`，起点 `s = position · L`，终点 `e = (position + width) · L`。渐变向量取 `s → e`，两个色标 `1 - top` 与 `1 - bottom`。

- 坡可以伸出图片外：`position = 0.5, width = 1` 时图片只看到坡的后半段，底边停在中间透明度。这正是 Kdenlive 的「按项目坐标定位渐变」观感，也避免把伸出部分压缩成更陡的坡。
- `width = 0` 时是硬边。零长度渐变在 canvas 里不可用，因此给 `1e-4` 的极小坡长（`FADE_MIN_SPAN`），视觉上仍是硬边。

### 3. 双向几何：不透明带 + 两条坡

`position` 是不透明带中心，`width` 是带宽。先把带夹进图片：

```
start = clamp(position - width / 2, 0, 1 - width)
end   = start + width
```

再生成色标：

- 若 `start > 0`：`t=0 → 1-top`，`t=start → 1`；否则起点边直接 `t=0 → 1`（没有上坡）。
- 若 `end < 1`：`t=end → 1`，`t=1 → 1-bottom`；否则终点边 `t=1 → 1`（没有下坡）。
- 相同 `t` 的色标合并。

于是：

- 双向预设 `0.5 / 0 / 1 / 1` → `0 → 1 → 0` 的对称三角，与旧双向逐像素相同。
- `position = 0.3, width = 0.2` → 上坡 20%、平台 20%、下坡 60%，可以做出明显不对称的双端淡出。
- 带宽贴近边缘时，带被平移进图片，贴边的一端自然没有坡；该端透明度不再可见。这是「带宽优先于位置」的取舍，避免带宽被静默缩小。

为什么用「不透明带中心 + 带宽」而不是「两条坡各自的位置/宽度」：后者需要 7 个参数并让面板明显变长；前者用同一组五参数就能表达不对称坡长，符合本次「比照 Kdenlive」的目标。

### 4. 模式切换即预设

`width` 在单向是坡长、在双向是带宽。若切换模式时沿用旧值，单向的 100% 会变成双向的整幅不透明带，看起来像渐隐失效。因此模式切换时把位置/宽度/顶部/底部透明度重置为目标模式的预设，角度保留；面板在模式字段旁用 `?` 提示这一行为。

备选是两种模式各存一套参数（多 4 个字段），但收益只覆盖「反复切换比较」的场景，不值得扩大持久化与校验面。

### 5. 渲染与缓存

`model.fadeProfile(item)` 返回纯数据：`{ from, to, stops: [{ t, alpha }] }`。`render.fillFadeMask` 用 `fadeGradientPoints` 得到整条轴的端点，再按 `t` 线性插值出渐变向量；色标偏移是 `(stop.t - from) / (to - from)`。这样单双向共用一条绘制路径，且几何可单测（Node 里不碰 canvas）。

`effectSignature` 必须包含 `fadePosition|fadeWidth|fadeTop|fadeBottom`，否则拖动新滑条会命中旧位图。`hasImageEffects` 也把四个字段计入，保证快速路径不会跳过非默认设置。

导出分支（`drawOneShotImage`）调用同一个 `fillFadeMask`，因此掩膜几何与分辨率无关；已用 1080×1920 实测画布 alpha 与导出 PNG 的颜色混合逐点一致。

### 6. 校验与兼容

- 字段缺失合法；存在则必须是有限数且落在 0–1，越界报「渐隐位置/转场宽度/顶部透明度/底部透明度无效」，与现有亮度/色相策略一致。
- 版本仍为 3；旧项目缺失字段时按当前模式的预设补齐，单双向旧观感不变。
- 序列化始终写出四个字段；`buildProject` 与 `buildBackgroundSet` 读取时按模式补齐。

## Risks / Trade-offs

- [`width` 语义随模式变化] → 面板动态标签 + 模式切换重置 + `?` 提示；不新增字段。
- [双向带宽贴边时该端透明度失效] → 视觉立即反馈；带宽优先于位置，避免静默缩窄不透明带。
- [硬边在 8-bit canvas 上出现锯齿] → 用 1e-4 轴长的极窄坡，依赖 canvas 抗锯齿；不引入逐像素处理。
- [滑条拖动导致缓存重建] → 与现有角度/亮度滑条同一路径；缓存签名完整覆盖新参数，不会复用错误位图。
- [双向参数含义需要解释] → 面板标签「不透明区宽度」+ 帮助提示；规格写清几何与默认映射。

## Migration Plan

- 无数据迁移：字段可选，旧项目按模式预设加载；保存后补齐。
- 回滚：revert 后新字段被旧构建忽略，项目仍可加载（只是渐隐退回旧几何）。
- 发布：`./build.sh` 无需调整，版本号不因本次改动变化。
