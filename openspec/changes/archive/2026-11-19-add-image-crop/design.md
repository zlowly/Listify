# Design

## Context

图片目前按完整矩形绘制：自由图片由 `element.x/y/width/height` 决定，背景图片由 `backgroundImageRect` 按 fit 或 `none` 矩形决定；`drawProcessedImage` 按目标矩形烘焙模糊/调色/渐隐，缓存键为资产、效果参数与尺寸桶。选择框、命中、缩放手柄、溢出提示和背景预览都直接使用这个矩形。裁剪要加入后，必须先决定「完整框」和「可见矩形」谁是存储、谁是派生，否则会出现二次裁剪、取整漂移与效果错位。动机见 `proposal.md`，行为见 `specs/`。

## Goals / Non-Goals

**Goals:**

- 裁剪可逆：调小或归零时原像素原位恢复，不重新适配、不累积漂移。
- 自由图片与背景图片共用一套裁剪数据、可见几何和渲染路径。
- 选择、命中、缩放、旋转、渐隐、预览、导出全部以可见矩形为准。
- 旧项目、旧草稿、无裁剪字段的图片按 0 正常加载。

**Non-Goals:**

- 不修改图片资产，不引入非破坏性编辑历史或多裁剪层。
- 不改变 fit 模式的既有语义，不为裁剪重新 cover。
- 不改变图形、文字、分类块的几何规则。
- 不新增运行时依赖或构建步骤。

## Decisions

### 1. 存完整框 + 裁剪，可见矩形派生

- 自由图片：完整框 = `element.x/y/width/height`。
- 背景 `none`：完整框 = `image.x/y/width/height`。
- 背景 fit：完整框 = `backgroundGeometry(pageSize, natural, fit)`；不存 x/y/width/height。
- 裁剪：`{ top, right, bottom, left }`，原图像素，整数，缺省 0。
- 换算：

```
scale      = frame.width / natural.width
visible.w  = (natural.width  - left - right)  * scale
visible.h  = (natural.height - top  - bottom) * scale
visible.x  = frame.x + left * scale
visible.y  = frame.y + top  * scale
```

选择「完整框为存储」而不是「可见框为存储」的原因：裁剪值归零时完整框不动，像素精确回到原位；可见框存储需要在每次裁剪编辑时改 x/y/width/height 并取整，反复调整会漂移，且取消裁剪只能按当前缩放反推，无法保证与原位置一致。代价是所有交互写入要先从可见框换算回完整框。

### 2. 可见矩形是交互几何

`elementCorners`、`hitTest`、`hitTestBackground`、`backgroundItemBounds`、`imageHandlePoints`、`rotateHandlePoint`、`pageOverflow`、背景缩略图与导出掩膜统一使用可见矩形。属性面板显示可见宽高，并给出原图与完整框摘要。

缩放换算：

```
newVisibleW = 目标可见宽
newScale    = newVisibleW / (natural.width - left - right)
newFrameW   = natural.width * newScale
```

移动直接平移完整框；等比锁定按可见宽高比；命中与手柄不包含被裁区域。这样选中框、点击和画面三者一致。

### 3. 旋转轴固定为完整框中心

旋转角继续存在条目上，绘制与拖拽都绕完整框中心。裁剪只改变可见矩形，不改变轴，因此裁剪调整不会改变旋转结果，取消裁剪也能精确恢复。旋转手柄的位置必须按完整框中心计算；当前 `rotateHandlePoint` 以可见框中心为轴，若直接沿用会在按下手柄时跳位。拖拽旋转期间在轴心绘制十字标记，松手移除；不常驻。

非对称裁剪后可见内容会偏离轴心，这是「裁剪只是遮罩」的直接结果；轴心十字用于解释。若改成绕可见中心，取消裁剪时可见内容会因轴心移动而偏移，与可逆性冲突，因此不采用。

### 4. 渲染：完整框烘焙，可见区取样

- 无效果快速路径：直接 `drawImage(img, sourceCrop, visibleRect)`，不分配离屏画布。
- 有效果：按完整框目标尺寸烘焙模糊/亮度/色相，渐隐几何按可见矩形计算但在完整框坐标系中绘制；最后只把可见子矩形画到画布。
- 这样模糊边缘仍有完整框内的像素参与，不会向透明衰减；渐隐仍贴可见边。
- 缓存键加入完整框尺寸与裁剪值；仅裁剪变化时允许重建位图，不得复用旧裁剪结果。
- 导出高清路径 `drawOneShotImage` 用可见∩页面作为掩膜，在完整框坐标中取样源裁剪。

### 5. 背景 fit、替换与只读

- fit 完整框由页面与 fit 实时计算，裁剪按原图像素内缩；页面尺寸变化只重排完整框，裁剪值不动。
- `cover` 裁剪后不再铺满页面，边缘露填充色；这是规格明确行为，不重新适配。
- fit → `none` 时把当前完整框写入 x/y/width/height，裁剪保持不变；不能写可见框，否则会二次裁剪。
- 替换图片（自由图片、背景图、预置图）先把裁剪归零，再按既有规则处理等比与定位；其它效果保留。
- 全局背景覆盖页只读：裁剪控件不渲染或禁用，画布不接受裁剪修改。

### 6. UI 与撤销

- 裁剪控件放在图片「高级」区域，复用页面边距/表格边距的 `.margin-cross` 十字布局与数字输入样式。
- 四个输入使用 `change` 提交，一次提交一条撤销记录，避免连续 `input` 刷栈。
- 高级关闭时裁剪输入不渲染；分组标题或「高级」开关旁显示「已裁剪」，与效果「已调整」分开表达。
- 图层行显示裁剪徽标，悬停给出四边摘要。
- 选中且裁剪非零时，画布覆盖层画完整框虚线与被裁区域压暗；这些图形只属于编辑辅助层，不进入导出与命中。
- 原图尺寸未加载时控件禁用；加载完成后启用并按当前值夹取。

### 7. 数据与兼容

- `project-io` 的图片元素与背景图片序列化新增 `crop`，加载时缺失补 0；负数、非有限数、非数字判为项目无效。
- `draft-store` 使用结构化项目，裁剪随项目保存，无需改 IndexedDB 结构。
- 不提升 `PROJECT_VERSION`：裁剪是可选字段，旧构建读取新文件时忽略未知字段；当前构建读取旧文件时补 0。若后续需要强制区分，再单独升级版本。
- 资产去重与引用计数不受裁剪影响。

## Risks / Trade-offs

- [完整框与可见框双坐标容易写错] → 把换算集中到 `model` 的纯函数，所有 UI/交互只调用；回归用例覆盖换算与边界。
- [非对称裁剪 + 旋转的偏心视觉] → 轴心十字 + 完整框虚线解释；不改成可见中心，避免破坏可逆性。
- [cover 裁剪后露背景色被当成 bug] → fit 下拉旁说明「裁剪后不重新铺满」，规格场景固定。
- [模糊在裁剪边缘出现透明晕] → 完整框烘焙、可见区取样；导出与画布共用同一路径。
- [取整造成边缘抖动] → 裁剪值按整数源像素存储，可见矩形允许小数；只在最终绘制时取整目标像素。
- [替换图片后旧裁剪裁到新图] → 替换统一先归零裁剪，再处理等比与定位。
- [缓存复用旧裁剪] → 缓存键包含裁剪与完整框尺寸；无效果路径不走缓存。

## Migration Plan

1. 模型与纯函数：裁剪归一化、完整框/可见框换算、边界夹取；补回归用例。
2. 渲染：图片与背景按源裁剪绘制；模糊/渐隐改用完整框烘焙；缓存键与导出掩膜。
3. 交互：选择、命中、缩放、旋转轴、fit→none、替换路径。
4. UI：裁剪十字、摘要、徽标、完整框辅助线、轴心十字。
5. 持久化：项目与草稿字段、旧文件补 0。
6. 手动与回归验证：自由图片、背景 fit/`none`、全局背景、旋转、导出、刷新恢复。

回滚：裁剪是新增可选字段，回滚到旧构建时字段被忽略，图片按完整画面显示；无需数据迁移。
