# Proposal

## Why

图形工具目前是"进入后一直留在模式里"的连续绘制工具，但实际使用几乎总是"画一个 → 立刻调色/调圆角"。连续绘制模式让用户必须记得手动退出，还会在画完后停在一种看不见的状态里：背景层的「＋ 图形」入口没有按下态，画布光标又被元素命中逻辑抢回成 `move`/`resize`。同时，图层栏背景行上还留着一个与属性面板「＋ 图片」重复的追加图标，造成入口冗余。按真实使用路径收敛为"单发绘制 + 自动选中 + 明确的模式反馈"即可消除这一整类困惑。

## What Changes

- 图形工具改为**单发**：一次激活只创建一个图形，创建后自动退出工具，不再支持连续绘制。两个入口（画布工具条 / 页面背景分组「＋ 图形」）行为对称。
- 创建后立即选中新图形：内容层选中该元素，背景层选中该背景条目（自动进入背景编辑态），属性面板直接显示图形属性，便于马上改色、改圆角、改边框。
- 模式反馈补齐：两个入口按钮在 armed 期间都显示按下态（`aria-pressed` + 激活样式，渲染期从工具状态派生）；画布指针在 armed 期间固定为十字，不再随命中元素变化；toast 文案改为单发语义。
- 取消路径保持并补全：`Esc`、再次点击同一入口、切换页面、选中其它对象均取消且不创建；在页面外空白处按下与现有"选中页面"一致地退出工具。
- **移除**图层面板背景行上的「＋」追加图片图标按钮；背景图片追加只保留属性面板「＋ 图片」一处入口。

### Modified Capabilities

- `shape-tool`: 「图形绘制工具」由连续绘制改为单发创建 + 创建后选中新图形；armed 期间固定十字光标；两个入口的统一模式反馈；页面外按下取消。
- `background-layer`: 背景层的图形创建改为"创建即选中该条目"；「＋ 图形」入口声明按下态与单发语义。
- `editor-shell`: 图层面板背景行不再提供追加图片图标按钮；无障碍场景中的按钮清单同步调整。

## Impact

- 主要代码：`js/app.js`（工具状态与入口指示）、`js/app-interactions.js`（创建后退出与选中）、`js/app-chrome.js`（光标短路与退出后刷新）、`js/ui.js`（删除背景行「＋」及其监听）、`js/ui-property-panel.js`（「＋ 图形」派生按下态）、`style.css`（`.btn.is-active`）。
- 不影响数据模型、项目文件格式、导出结果、撤销粒度与其它背景行为。
- 需求文档 `docs/歌单生成器需求.md` 与 `README.md` 中"创建后保持激活、可连续绘制"的描述需同步改写。
- 无新增依赖、无构建步骤变化；纯逻辑 Node 测试不受影响，交互变化用浏览器手动/`agent-browser` 验证。
