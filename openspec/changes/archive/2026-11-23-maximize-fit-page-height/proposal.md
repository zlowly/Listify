# Proposal

## Why

“适应窗口”给页面四周各留出可视短边 8% 的留白（上限 72px）。竖版歌单（如默认 1080×1920）在常见窗口下由高度决定缩放，这圈留白让页面上下各空出 65–72px，页面只占画布高度的约 84%，编辑时看不清歌名细节，与“尽量铺满窗口”的预期不符。

## What Changes

- 适应窗口的留白改为按方向区分：左右保留较宽松的呼吸空间，上下压缩到固定的小边距（≈16px），让竖版页面在高度受限时尽可能铺满画布。
- 适配比例仍取“宽度约束/高度约束”的较小值，页面在适应窗口下仍完整可见、居中、无滚动条。
- 选中的页面手柄、边距参考线、空态提示等浮动装饰的定位随新的上下留白一起调整；固定比例模式与缩放百分比行为不变。
- 不改变页面尺寸、元素坐标、项目 JSON 或 PNG 导出结果。

### Modified Capabilities

- `canvas-view`: “适应窗口”的页面留白从四周统一 8% 改为左右保留、上下最小化，并明确页面在适应窗口下占满纵向可视区且不产生滚动条。

## Impact

- `js/app-viewport.js`：`measureCanvas` 的适配比例计算与 `syncGeometry` 的舞台尺寸/原点计算需区分横向、纵向留白。
- `openspec/specs/canvas-view/spec.md`（经本变更的 delta 更新）。
- 可能同步 `DESIGN.md` 中关于适应窗口留白的描述。
- 不影响数据模型、持久化、导入导出、渲染管线与零构建约束。
