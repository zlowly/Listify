# Design

## Context

`js/app-viewport.js` 负责一切视图几何。`measureCanvas()` 用一个统一的 `viewport.padding`（`min(72, max(24, min(宽, 高) × 0.08))`）同时约束横向和纵向的适配比例；`syncGeometry()` 再用它计算舞台尺寸、页面原点和居中位置。默认页面为 1080×1920 竖版，常见窗口下高度是约束方向，因此这个 8% 留白直接吃掉约 15% 的可见高度。页面装饰、选择手柄和边距参考线绘制在覆盖整个画布面板的独立 canvas 上，不随舞台裁剪。

约束：保持零构建与经典脚本；适应窗口必须无滚动条；缩放比例上限沿用 1.6；不修改项目数据与导出。

## Goals / Non-Goals

**Goals:**

- 高度约束生效时，页面上下留白每侧降到 16px，竖版页面显示高度提升约 14%。
- 左右留白保持现有的呼吸空间，横版页面布局不变。
- 页面继续居中、完整可见、无滚动条；窗口尺寸变化时立即重算。
- 选择手柄、边距参考线、空态提示的屏幕位置与新的页面位置保持一致。

**Non-Goals:**

- 不改顶栏、左右侧栏、浮动工具条的尺寸或可折叠性。
- 不改缩放模式、百分比范围、步进、指针锚定缩放和滚动语义。
- 不改变页面尺寸、元素坐标、项目 JSON、草稿存储或 PNG 导出。
- 不为极小页面尺寸调整 1.6 的适配放大上限。

## Decisions

**1. 拆分横纵留白，而不是统一缩小。**
在 `measureCanvas()` 中保留 `viewport.paddingX`（原公式），新增 `viewport.paddingY = 16`。适配比例改为：

```
fitScale = clamp(min(
  (availableWidth  - paddingX * 2 - 1) / pageW,
  (viewport.height - paddingY * 2) / pageH
), 0.05, 1.6)
```

替代方案：把统一 padding 直接降到 16px——更简单，但横版页面左右会贴边，失去呼吸空间；或用 0 留白——页面边框与缩放手柄视觉上过于拥挤。拆分成两个值只影响几何计算，风险最小。

**2. 舞台尺寸与原点分别使用对应方向的留白。**
`contentW` 用 `paddingX`，`contentH` 用 `paddingY`；溢出时原点取 `paddingX`/`paddingY`，未溢出时仍按可用区域居中。这样宽度受限时页面仍水平居中，高度受限时页面上下正好各留 16px。

**3. 保留横向 `-1` 安全量，并让纵向留白精确等于 16px。**
宽度约束保留 `-1`：防止亚像素舍入把页面算得比可视区宽 0.5px 而触发滚动条。高度约束使用精确的 `paddingY * 2`，居中原点 `(viewport.height - pageH * scale) / 2` 因此正好是 16px，页面高度为 `viewport.height - 32`；舞台尺寸的 `+0.01` 容差足以吸收浮点误差，不会产生滚动条。若高度也减 1，居中会把多出的 1px 各分 0.5px，实测上下留白变成 16.5px，与规格的“≤16px”冲突。

测量循环保留多遍比较，并扩展为最多 3 遍：初始化时页面画布以未缩放的整页尺寸进入布局，第一遍测量会碰到临时滚动条（可视高度少 10px），因此在每遍计算后先应用当前变换，下一遍再读取真实可视尺寸。进入适应窗口时把滚动容器的 `overflow` 设为 `hidden`，让可视尺寸始终等于画布面板尺寸，避免从固定比例切回时残留滚动条影响测量；切到固定比例时恢复 `auto`。适应窗口本来就不产生滚动条，因此行为等价。

**4. 不改装饰层与覆盖层。**
页面阴影、边框、选择手柄和边距参考线画在 `#overlay` / `#overlay-chrome` 上，覆盖整个 `#canvas-pane`，不受 16px 舞台留白裁剪；空态提示按画布可视区居中，语义不变。无需新增 DOM 或 CSS。

**5. 适配上限仍是 1.6。**
当页面本身很小时，1.6 的放大上限会先于高度约束生效，此时上下留白可能大于 16px；这是既有的“最多放大到 160%”行为，规格已限定留白规则只在高度约束决定比例时成立。

## Risks / Trade-offs

- [选择手柄在 16px 内显得局促] → 手柄与边框绘制在独立的覆盖层上，不被裁剪；16px 足够容纳当前约 7px 半径的手柄，验收时在页面四角点选确认可拖动。
- [页面视觉上过于贴边，失去画布背景的分隔感] → 16px 仍保留一条可见的画布底色与页面阴影；若观感不佳，只需调大 `paddingY` 常量，不涉及结构改动。
- [极窄窗口下左右留白挤压页面] → 保持原有 `paddingX` 公式与其 24–72px 范围，行为不变。
- [没有覆盖适配几何的纯逻辑测试] → 该计算依赖真实 DOM 可视尺寸；用 `agent-browser` 在多个窗口尺寸下读取 `L.viewport.pageScreenRect()` 与 `#canvas-scroll` 的 `clientHeight`，断言上下留白与无滚动条，再跑现有 `node --test scripts/checks/*.test.js` 保证无回归。

## Migration Plan

无数据迁移。适应窗口比例在每次测量时重算，刷新后自然采用新留白；固定比例模式不读取该值。回滚只需恢复单一 `padding` 的计算。
