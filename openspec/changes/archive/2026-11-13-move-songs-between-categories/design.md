# Design

## Context

歌名格是一个装着 `<input>` 的 `.playlist-editor-cell`，删除按钮绝对定位在右上角；网格由 `renderGrid()` 整体重建，分类行由 `renderRail()` 重建。编辑器已有工作副本与「应用/取消」，跨分类移动只需改工作副本里的两个数组。

项目里已有两种现成的拖拽实现：左侧分类面板用原生 HTML5 拖放（`draggable="true"` + `DataTransfer` + `dragover`/`drop`），画布元素用 overlay 上的 pointer 事件。本次照搬前者，因为目标判定、自动滚动和拖拽图像都由浏览器提供，代码量最小。详见 proposal.md 的动机。

## Goals / Non-Goals

**Goals:**

- 从把手开始的单首拖拽，落在分类行上追加到末尾。
- 拖拽不干扰输入框的选词、光标和键盘操作。
- 移动与现有工作副本、校验、撤销、摘要机制无缝衔接。

**Non-Goals:**

- 不做触摸端拖拽、不做分类内重排、不做精确插入、不做多选、不做键盘替代。
- 不改数据格式、不改画布排版规则、不改分类的增删能力。

## Decisions

### 原生 HTML5 拖放，而不是 pointer 事件

分类面板已经在用同一套 API，交互一致；pointer 方案需要自己做命中判定、滚动跟随和拖拽残影，只为换取触摸支持——而触摸不在本次范围内。代价是 iOS 等触摸浏览器上把手拖不动，这一点在风险里标明。

### 把手是唯一 draggable 元素，且不进入 Tab 序列

输入框保持可选中、可编辑；把手设 `draggable="true"`、`tabindex="-1"`、带「拖动〈歌名〉」的可读标签。把手可聚焦但不进 Tab 序列，避免键盘用户停在一个只能拖、按了没反应的控件上——既然明确不做键盘替代，就不给假的键盘入口。

### 拖拽起点捕获「分类索引 + 歌名索引 + 歌名」，落点时二次校验

`dragstart` 时把三者记在闭包里，`DataTransfer` 只负责让浏览器认为这是一次合法拖拽（并附带 `text/plain` 歌名，便于调试与拖出）。`drop` 时先确认源分类该位置仍然是同一首歌，再 `splice` + `push`；不匹配就放弃并清理高亮。这样即使拖拽期间发生意外重渲染，也不会把别的歌搬走。

### 目标只认分类行，落点固定追加

分类行本身就是 drop 目标：`dragenter`/`dragover` 里 `preventDefault()` 表示可放下，加高亮 class；`dragleave` 用 `relatedTarget` 是否仍在行内来过滤子元素造成的抖动；`drop` 与 `dragend` 都清理高亮，避免拖到窗外松手后高亮卡住。拖回当前分类按无操作处理，不重排——分类内顺序本来就不影响画布，多一套语义只会让落点难以预测。

### 落点后走既有结构刷新，不新增提交路径

`drop` 只做数组搬运，然后调用 `refreshAfterStructureChange()`：重建网格与分类行、重算校验、更新计数。焦点回到源分类的同一序号（若已越界则落到添加格），与删除歌曲后的焦点行为一致。应用时现有 `diffSongChanges` 会自然把搬家算成目标分类新增、源分类删除，无需在 app 层加特判。

### 编辑中的焦点格必须防回写

`renderGrid()` 会整体替换 `grid.innerHTML`，聚焦中的输入框被移除时浏览器会补发 `blur`。若 blur 监听无条件把值写回 `currentCategory().songs[index]`，切换分类、排序、删除或移动后的新数组会在同一序号被旧值覆盖（实测出现重复歌名、丢失原歌）。两道防护：`selectCategory()` 改 `activeIndex` 前先 `commitActiveElement()`；`bindCellInput()` 记录绑定时的分类与 `gridRenderToken`，blur 时分类或轮次不一致直接返回。

### 视觉：把手与 drop 目标复用现有 token

把手用弱化的 `--muted` 图标，仅在格子悬停或 `:focus-within` 时出现；drop 目标用 `--blue-soft` 底加半透明蓝环，与「当前选中分类」的实心浅蓝底区分开。具体取值按 DESIGN.md 的现有约定实现。

## Risks / Trade-offs

- **触摸设备无法拖动** → 本次明确不做；桌面鼠标/触控板正常。后续要做移动端时，可在此语义不变的前提下换成 pointer 实现。
- **`dragleave` 在子元素间来回触发导致高亮闪烁** → 用 `relatedTarget` 判断是否真正离开分类行，并在 `dragend` 统一兜底清理。
- **把手与删除按钮、长歌名挤在同一格** → 把手放左侧，输入框增加左内边距；在 900px 窗口与 140px 最窄列宽下验证不重叠。
- **拖到窗外或按 Esc 取消拖拽** → 浏览器发 `dragend`，清理高亮且不改数据；与「拖到空白处」一致。
- **移动造成源分类空掉** → 分类保留为 0 首，与删除最后一首的既有行为一致。

## Migration Plan

无数据迁移，项目格式不变。回滚即移除把手与 drop 监听，已移动的数据仍是合法的歌单顺序。

## Open Questions

- 拖拽图像用把手本身还是整个格子：纯视觉细节，实现时按拖拽清晰度择一，不影响行为。
