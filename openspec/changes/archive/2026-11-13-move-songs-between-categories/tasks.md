# Tasks

## 1. 拖拽把手

- [x] 1.1 在 `renderGrid()` 的每个歌名格中加入拖拽把手（`draggable="true"`、`tabindex="-1"`、可读的「拖动〈歌名〉」标签），悬停或格内聚焦时显示；验证：1280px 与 900px（140px 最窄列）下把手不与删除按钮、输入文字重叠，Tab 序列不会停在把手上。
- [x] 1.2 只在把手上绑定 `dragstart`：捕获分类索引、歌名索引与歌名，设置 `effectAllowed = 'move'` 并在 `DataTransfer` 写入歌名；验证：在歌名输入框内按下并拖过文字只产生选词，不触发拖拽；从把手拖动时能出现浏览器拖拽态。

## 2. 目标分类与落点

- [x] 2.1 分类行作为 drop 目标：`dragenter`/`dragover` 阻止默认并加高亮 class，`dragleave` 用 `relatedTarget` 过滤子元素抖动，`dragend` 与 `drop` 统一清理高亮；验证：拖过多个分类行时同时只有一个行高亮，拖出窗口或按 Esc 后高亮清除且数据不变。
- [x] 2.2 实现 `drop`：拖回当前分类按无操作返回；否则先校验源分类该序号仍是拖拽时那首歌，再 `splice` 源、`push` 到目标分类末尾，然后 `refreshAfterStructureChange()`，焦点回到源分类同一序号（越界则落到添加格）；验证：拖「晴天」到「民谣」后两侧顺序与「N 首」计数正确，源分类只剩其余歌，焦点位置合理。
- [x] 2.3 覆盖空分类与最后一首：把某分类唯一一首拖走后，源分类显示「0 首」且仍可继续添加；验证：拖走后该分类仍在左侧列表、点击可进入并看到添加格。
- [x] 2.4 补样式：把手显隐、拖拽中的目标行高亮（与选中态可区分）、把手不改变输入框的聚焦表现；验证：拖动经过时目标行高亮唯一可见，输入框聚焦仍是蓝描边 + 半透明蓝环。

## 3. 提交、校验与摘要

- [x] 3.1 验证工作副本语义：拖拽后点「取消」并确认放弃，两分类数据与画布不变；拖拽后「应用」，一次撤销回到移动前；验证：连续走两条路径并比对歌单 JSON 与画布截图。
- [x] 3.2 验证校验跟随：把空歌名或与目标分类同名的歌拖进去后，相关格子标红、分类行报错、「应用」禁用；修正后恢复；验证：重复与空名两种情形各走一遍，状态计数正确。
- [x] 3.3 验证摘要：仅做一次跨分类移动后应用，提示为目标分类新增一首、源分类删除一首，不出现「修改」；验证：读取 toast 文案与通报数字。
- [x] 3.4 确认无关数据不变：移动并应用后，未涉及分类的名称、块位置尺寸、表格结构、填充顺序与手动列宽保持不变；验证：对带手动列宽的另一个分类移动前后比对属性面板数值。

## 4. 集成验证

- [x] 4.1 与现有编辑动作交错：先排序再拖动、先拖动再排序、拖动后在添加格粘贴多行，均不出现重复移动或错位；验证：按顺序执行三种组合并检查网格顺序与计数。
- [x] 4.2 验证画布结果：只移动一首并应用后，源分类块按剩余歌名重新排版，目标分类块包含新歌且排在末尾；验证：画布上两个块的文字顺序与导出的 PNG 一致。
- [x] 4.3 边界走查：拖到空白处、拖回原分类、拖拽中途按 Esc、关闭编辑器时的放弃确认，均无脏数据或残留高亮；验证：四项逐一操作，关闭后重开编辑器顺序与操作前一致。

## 5. 验证中发现的补充修复

- [x] 5.1 切换分类前先提交当前格：`selectCategory()` 在改 `activeIndex` 之前调用 `commitActiveElement()`，避免聚焦格仍属于旧分类时把值写进新分类。
- [x] 5.2 用渲染轮次令牌阻止旧输入框回写：`renderGrid()` 每次重建递增 `gridRenderToken`，`bindCellInput()` 绑定时的令牌与当前不一致则 blur 直接返回；验证：聚焦某格后点击排序、删除、移动或切换分类，歌名不再互相覆盖，校验计数正确。
