# Proposal

## Why

歌名目前只能改、删、加，跨分类挪一首只能「复制歌名 → 切分类 → 粘贴 → 回原分类删除」，而且删掉再添加会丢掉它原来的位置。编辑器里已经有分类导航和工作副本，缺的只是一个直接的搬运动作。

用户最初设想按住 Ctrl 拖动；确认后改为**只从拖拽把手拖、不依赖修饰键**，落点统一追加到目标分类末尾。这样既不和输入框选词冲突，也避开了 macOS 上 Ctrl+点击是右键手势的问题。

## What Changes

- 每个歌名格增加一个拖拽把手，悬停或格内聚焦时显示；**只有把手可拖**，在输入框里选词、点按、输入都不会触发拖拽。
- 拖到左侧分类行时目标行高亮；松手后该歌从当前分类移除，**追加到目标分类的歌名末尾**。
- 单首移动。拖回当前分类、或拖到空白处不产生任何修改，也不制造脏状态。
- 移动只改编辑器工作副本：取消丢弃，应用时与其他编辑合并为一步撤销；源分类可以变成 0 首，但分类本身保留。
- 校验跟随歌名移动：被移到别处的空歌名、重复歌名照常标红并禁用应用，不因拖拽被特殊放行或静默拦截。
- 摘要体现两侧变化：目标分类计「新增」，源分类计「删除」，不把搬家误报成「修改」。

## Capabilities

### New Capabilities

（无）

### Modified Capabilities

- `playlist-editing`: 新增「歌名跨分类拖拽」需求——把手的拖拽起点、目标分类与落点、工作副本提交语义、校验跟随规则；现有需求（多列网格、键盘编辑流）行为不变。

## Impact

- `js/ui.js`：`renderGrid()` 的格子结构增加把手，分类行作为 drop 目标，拖拽生命周期（dragstart / dragover / drop / dragend / 清理高亮）。
- `style.css`：把手显隐与拖拽中的目标高亮；复用现有焦点环与颜色 token。
- `js/app.js`：无需改逻辑——移动在应用后表现为目标分类新增一首、源分类删除一首，现有摘要与撤销已覆盖。
- 明确不做：键盘替代操作、多选批量移动、插入到目标分类的指定位置、分类内重排、触摸拖拽。
