# Proposal

## Why

页面一旦出现歌名等文字内容，背景图片的拖动/缩放、透明度/模糊滑条的拖动、X/Y 数值框箭头的连续步进都会明显卡顿。根因：每个交互事件都触发一次整页全量重绘，过程中每首歌的文字布局（逐字 measureText）被重复重算 2~4 次，且每次重绘伴随强制 DOM reflow；背景图的数值输入还会整面板重建 DOM 导致输入框失焦、连续步进中断。卡顿程度随歌曲数量线性增长，多歌页面下交互不可用。

## What Changes

- **重绘合帧**：同一动画帧内的多个交互事件（拖拽、滑条、数值步进）合并为至多一次画布更新；连续交互期间跳过几何重测量（强制 reflow），仅在页尺寸/窗口变化时执行。
- **渲染分层**：背景层（填充色 + 背景图片）与内容层（分类/文字/自由图片）分别绘制到独立画布并叠加；背景图片的位置/缩放/旋转/透明度/模糊调整只重绘背景层，不触发内容层文字的重排与重绘。视觉结果 MUST 与现有全量重绘路径一致。位图比例按像素预算收敛，超大页尺寸不再产生数百 MB 的两层位图。
- **页面装饰与交互分层**：overlay 拆为静态装饰层（页面阴影、边框、边距参考线、溢出徽标、页尺寸手柄）与交互层（选中框、手柄、表格分隔线）；拖拽背景图时装饰层与溢出检测不重算。
- **布局缓存生效**：`layoutCategory` 已有 `_layoutByMode` 缓存槽但只写不读，改为按**布局签名**（歌曲列表、元素宽度、字体测量字段、行高、表格配置、编辑模式；不含颜色/阴影/描边）命中复用；同一帧内通过帧令牌共享一次签名计算，绘制、溢出检测、选择框共享同一份布局结果。
- **背景图数值输入就地提交**：背景图片 X/Y/宽/高/旋转的数值输入（含原生箭头与 Ctrl+方向键快速步进）提交时只更新模型、就地刷新输入显示并只重绘画布，MUST NOT 重建整个属性面板；输入框 MUST 保持焦点，连续步进 MUST 持续生效。
- **（可选）文字绘制成本**：两端对齐的逐字 metrics 与阴影双遍绘制在布局阶段预计算，降低内容层重绘成本。

无 BREAKING 变更：项目 JSON、数据模型、导出输出均不变；所有操作的手感与视觉结果保持现有行为，仅响应速度提升。

## Capabilities

### New Capabilities

（无）

### Modified Capabilities

- `canvas-view`：新增需求「重绘合帧与图层更新解耦」——交互事件按帧合并，每个画布层每帧至多一次更新，调整背景图片不重算内容层文字布局；页面装饰层仅在几何或内容变化时重绘；分层绘制的视觉结果与全量重绘一致。
- `editor-shell`：新增需求「面板输入就地提交」——属性面板数值/滑条类输入提交后不重建整个面板，输入焦点与面板滚动位置保留，连续步进持续生效。

## Impact

- `js/app.js`：`redraw()` 改为脏标记 + rAF 合帧、几何/变换/zoom UI 移出热路径、双层画布初始化与像素预算、`#overlay-chrome` 装饰层与 `overflowDirty` 缓存、交互入口改置脏标记、`setBackgroundImageValue()` 就地提交。
- `js/render.js`：屏幕路径复用 `drawBackground` + `drawPage({includeBackground:false})`；`pageOverflow`、`elementBounds`、`drawSelection`、`tableDividers` 复用同一份布局结果（导出路径不变）。
- `js/layout.js`：`_layoutByMode` 按布局签名命中读取（仅含布局输入，不含纯绘制字段），帧令牌避免同帧重复计算。
- `js/ui.js`：背景图数值输入提交不再走 `ui.renderAll()`；背景类样式/滑条事件传入 `layers:['bg','overlay']`，避免误置内容层脏标志。
- `index.html` / `style.css`：`#leafer-view` 内背景/内容双层画布、`#overlay-chrome` 装饰层结构与样式。
- 不受影响：`js/model.js`（数据模型）、`js/io.js` / `js/export.js` / `js/playlist-export.js`（导入导出）、预置素材管线、`build.sh` 发布流程。
- 验证：浏览器 `file://` 手工验证（`samples/` 歌单，对比有/无歌曲时背景图拖动、滑条、箭头步进的流畅度）；DevTools Performance 确认背景图操作帧内无内容文字测量。
