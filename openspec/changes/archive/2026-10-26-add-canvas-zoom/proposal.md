# Proposal

## Why

画布目前每次重绘都强制按窗口大小适配并居中（`computeViewport()` 把缩放限制在 0.05–1.6 之间），用户无法按固定比例查看页面。1080×1920 的页面在常见窗口下只能显示到约 40%–50%，歌名、列宽、边距和选中手柄都挤在一起；反过来，用户也无法放大到 100% 以上逐像素校对位置。缺少视图缩放，等于缺少印前工作最基本的近看/远看两档视角。

本次调整只增加“视图缩放”这一层能力：缩放改变的是画布视图的显示比例，不改变页面尺寸、元素坐标或导出结果。

## What Changes

- 画布增加独立的视图缩放状态：默认“适应窗口”（保留现有自适应行为），用户可切换为固定百分比。
- 在画布工具条中增加缩放控件：缩小、当前比例（可输入/选择）、放大、适应窗口（重置）；百分比按 5% 或预设档位步进。
- 支持 `Ctrl`/`⌘` + 滚轮在画布上以指针位置为锚点缩放；普通滚轮/触控板滚动查看区域。
- 当页面按当前比例超出画布可视区域时，画布出现横向和/或纵向滚动条；用滚动条、滚轮或触控板移动观看区域。页面仍小于可视区域时保持居中且不显示滚动条。
- 缩放为视图状态：不写入项目 JSON，不改变页面尺寸和元素坐标，不影响 PNG 导出内容和分辨率；切换页面、编辑元素、窗口尺寸变化后保持用户选择的比例（“适应窗口”模式下随窗口重算）。
- 浮动工具条、页签和空状态提示固定在画布可视区域，不随内容滚动；命中测试、选择框、边距参考线、列分隔手柄和行内文字编辑按滚动后的实际位置对齐。
- 明确区分“视图缩放”和“页面尺寸”：属性面板中的页面宽高仍是项目级设置，缩放控件不修改它们；放大视图不会被当成页面变大。

## Capabilities

### New Capabilities

- `canvas-view`: 画布视图的缩放与滚动行为——缩放模式与范围、缩放控件与快捷键、滚动条出现条件、视图状态的生命周期，以及与页面尺寸、编辑命中和导出的边界。

### Modified Capabilities

无。`editor-shell` 只要求画布工具条承载分页与插入动作，新增缩放控件不改变该约定；`page-editor` 的页面尺寸、边距和元素编辑语义保持不变，这里新增的是查看层能力。

## Impact

- `index.html`：画布区加入可滚动容器与缩放控件（缩小/比例/放大/适应窗口），保留现有 `#leafer-view`、`#overlay`、`#canvas-toolbar` 的职责。
- `style.css`：新增画布滚动视口、滚动条、缩放控件组样式；调整画布容器的 `overflow` 与层级，确保工具条不随内容滚动、空态提示仍居中于可视区域。
- `js/app.js`：`viewport` 增加缩放模式与固定比例；`computeViewport()` 拆分“适配比例”和“当前比例”；滚动偏移并入 `offsetX/offsetY` 与 `toScreen/toPage`；新增滚轮缩放、滚动同步与滚动条尺寸计算；缩放变化后保持锚点。
- `js/ui.js`：绑定缩放控件、同步百分比显示与可用状态；窗口 `resize` 时区分“适应窗口”和固定比例。
- `DESIGN.md`：更新画布一节，补充缩放控件位置、比例范围、滚动行为和“视图缩放 ≠ 页面尺寸”的说明。
- 不新增依赖、不引入构建步骤、不需要网络；仍是 `file://` 可打开的零构建页面。项目 JSON 格式不变，无迁移。
