# Design

## Context

图层行的 HTML 由 `js/ui.js` 的 `renderLayerPanel` 一次性拼装并整体写入 `innerHTML`（`ui.js:511-628`），每次 `renderAll` 都会重建全部行。行内图标目前是固定字形：图片 `▧`、方形 `▢`、菱形 `◇`、文字 `T`、分类 `▤`、背景组 `▦`（`ui.js:521-547`、`598-605`）。

两项现成能力决定了实现方式：

- 每个图片资产在装入时就已经建立对象 URL（`js/assets.js:37-49` 的 `addBlob`），项目加载路径 `project-io.installAssets`（`project-io.js:484-490`）也会把 `urls` / `images` 一并装回，所以缩略图可以同步取得字符串，不需要异步等待，也不需要读像素。
- 图形的 `color` 与 `mode`（`fill` / `stroke`）是项目内的精确值（`js/shape.js:24`、`SHAPE_MODES`），无需从画布反推。

行几何固定在 22×22 的 `.layer-icon` 槽位里（`style.css:398-408`），并且既有 spec 要求行尺寸、内边距、排版与悬停样式不因控件替换而改变。

## Goals / Non-Goals

**Goals:**

- 让同类行在列表里可被一眼区分：图片靠缩略图、图形靠自身颜色与填充方式。
- 让图片行有稳定的口语锚点（`图片 N`），且编号规则在内容层与背景层一致。
- 零新增持久化数据、零项目 schema 变更、零新模块与 `index.html` 顺序变化。

**Non-Goals:**

- 不在图层面板里烘焙裁剪、调色、渐隐或透明度的最终外观；缩略图只回答「这是哪张素材」。
- 不做平均色 / 主色提取。那需要 `getImageData`，在 `file://` 下有 canvas 被污染的风险，而它提供的信息量不如缩略图。
- 不改变行高、内边距、字号、悬停反馈，也不引入行内搜索、悬停画布高亮或缩略图放大预览。
- 不给文字行按文字颜色着色、不给图形行加序号（本次只解决图片与图形的辨识与图片编号）。

## Decisions

### 1. 缩略图直接用资产对象 URL，不做二次缓存

`L.assets.getUrl(assetId)` 返回的 `blob:` URL 直接作为 `<img src>` 填进既有图标槽位：

```
<span class="layer-icon layer-thumb" aria-hidden="true">
  <img src="blob:…" alt="">
</span>
```

CSS 用 `width/height: 100%` + `object-fit: cover` + 继承圆角，槽位尺寸仍是 22px，行几何不变。

- 备选 A：按 assetId 生成 48px data-URL 小图缓存。首次成本更高，且要处理缓存失效；先不做，但作为性能退路保留（见风险）。
- 备选 B：`background-image: url(blob:…)`。省掉一个元素，但加载失败时无法优雅回退到通用图标，且不便表达透明图的描边提示，因此不选。
- 备选 C：平均色/主色色条。需要 `getImageData`，照片平均色高度同质，辨识力弱于缩略图；放弃。

### 2. 缩略图只反映原始资产

不调用 `render.processedImage` 一类烘焙逻辑：那套缓存按尺寸分桶、按像素预算淘汰（`render.js:100-245`），把面板渲染耦合进画布缓存会带来失效与内存问题。副标题已经承担「已裁剪」「旋转 N°」这类状态信息（`ui.js:537-542`），缩略图只做身份识别。

### 3. 图形行用 DOM 迷你图形表达颜色与填充方式

不把 `◢` 之类字形染色（无法表达描边），也不引入位图：

```
<span class="layer-icon" aria-hidden="true">
  <span class="shape-mark is-diamond is-stroke" style="--shape-color:#3b82f6"></span>
</span>
```

- 实心：`background: var(--shape-color)`；描边：`border: 2px solid var(--shape-color)`、内部透明。
- 菱形用方形旋转 45° 实现，尺寸按外接框内缩，保证与外框相切时视觉上不溢出槽位。
- 图形 `opacity` 极低、颜色过浅（如 `#FFEB3B`、接近白色）时，标记不透明度设 0.35 下限并加一圈淡描边；图标用于识别，忠实还原反而会让它消失。

### 4. 序号按「同类型、自底层向顶层」计数，内容层与背景层一致

编号从 1 起、只在同类条目内递增，与背景子行现有方向一致（`ui.js:615` 目前用 `realIndex + 1`，即自底向上）。

- 变更点：背景子行现在按**全部条目**计数，混排时「图片 2」的 2 可能来自中间的图形；本设计改为只数图片，图形不占号。
- 备选：自上而下编号（更贴合阅读顺序）。它会让所有既有背景标签反向变化，超出本次必要范围，且与「层级序号」的语义冲突，因此不选。
- 实现约束：先按模型顺序一次遍历建立 `id -> 序号` 映射，再拼行；不要在每行里 `filter` 计数（会退化为 O(n²)）。

内容图片行与背景图片子行都用同一套映射规则；图形行保持无序号（颜色已承担区分职责）。

### 5. 装饰内容不进入无障碍名称

缩略图与迷你图形放在既有 `.layer-icon` 内，该容器已经声明 `aria-hidden="true"`（`ui.js:552`、`616`），`<img>` 用 `alt=""`。行的 `aria-label` 仍然由「名称 + 副标题 + 操作提示」组成；序号作为可见文本自然进入朗读，不新增焦点目标。

### 6. 回退与失效路径显式处理

`getUrl` 返回空、资产不存在或 `<img>` 加载失败时，保留现有的 `▧` 字形，不插入空 `<img>`。草稿恢复与项目导入都可能在资产缺失状态下渲染（`draft-store.js:407-415` 会清理缺失引用），因此该分支必须与正常行在选中、拖拽、删除上完全等价。

## Risks / Trade-offs

- [每次 `renderAll` 全量重建行，N 个 `<img>` 被反复创建] → 对象 URL 相同，浏览器按 URL 复用解码结果，通常无抖动；若实测某浏览器在频繁选中时闪烁或卡顿，改为在 `L.assets` 上缓存 48px data-URL 小图（仍只用 `drawImage`，无需读像素）。
- [首次展开含大量原图的页，缩略图触发解码] → 这些图片在画布渲染时已经解码并缓存在 `L.assets.images`，复用同一 URL，额外成本主要是缩略尺寸的绘制。
- [透明 PNG 在浅色行背景上几乎不可见] → 槽位保留底色并加一圈内描边，既标示边界也不引入 22px 棋盘格噪点。
- [缩略图与画布最终外观不一致（裁剪/调色/渐隐）] → 明确为非目标；副标题保留「已裁剪」，`aria-label` 不变。
- [背景子行混排编号变化被当作回归] → 提案中标记为 BREAKING，并补「图片与图形混排编号」场景；排序、选择、拖拽与撤销记录数量不变。
- [编号自底向上与列表自上而下的阅读顺序相反] → 与现有背景子行方向一致；若验收认为反直觉，翻转映射即可，只影响一处编号函数。
- [Node 回归套件不覆盖 DOM/画布] → 本变更靠浏览器人工验收与 `agent-browser` 自动化检查；可在 `js/dev-checks.js` 增加「每行 img.src 与对应 assetId 的对象 URL 一致」的断言，该文件不进入发布包。

## Migration Plan

无数据迁移：不改项目 JSON、草稿库结构或资产库。发布即为 `VERSION` 递增后的常规 `./build.sh` 出包；回滚只需还原 `js/ui.js` 与 `style.css` 两处渲染与样式改动。
