# Design

## Context

见 `proposal.md`。当前实现把背景存在项目级 `backgrounds[]`，页面用 `backgroundId` 引用；全局背景是 `unifiedBackground` + `unifiedBackgroundId` 的非破坏覆盖，另有固化与副本两个批量动作。渲染、导出、草稿与项目文件都围绕这三个概念展开，纯逻辑回归在 `scripts/checks/`。

约束：零构建、`file://` 可运行；项目 JSON 必须继续支持旧版本导入；页面背景的图片效果、定位、预置素材与页面裁剪行为全部保留；模块依赖方向不变（`model`/`render` 不反向依赖 `ui`/`app`）。

## Goals / Non-Goals

**Goals:**

- 背景归属从「项目库」收敛为「页面属性」，项目文件只保存页面背景。
- 用一个可自述的规则表达跨页统一：有一个全局来源页，后设置覆盖先设置，取消即无。
- 全局期间非来源页的背景只读，避免「改了看不见」的歧义。
- 旧项目（v1–v3）与旧草稿无损迁移到 v4。

**Non-Goals:**

- 不实现跨项目、跨浏览器的背景素材库。
- 不保留背景命名、使用页数、复制/删除背景、固化到所有页、本页独立副本。
- 不改变背景图片的定位、裁剪、调色、渐隐、旋转、预置素材与导出规则。
- 不引入新依赖、构建步骤或 IndexedDB 版本升级。

## Decisions

### D1：页面拥有背景

`page.background = { color, images: BackgroundImage[] }`，始终存在；`BackgroundImage` 复用现有字段与 ID 生成规则。移除 `project.backgrounds`、`page.backgroundId`、`unifiedBackground`、`unifiedBackgroundId`，新增 `project.globalBackgroundPageId`（可为 `null`）。

理由：页面背景的读取路径变成 `page.background`，渲染、命中、导出、草稿与 JSON 都少一层间接。替代方案是保留库但隐藏管理 UI，仍要维护引用计数与删除保护，没有减少状态。

### D2：全局背景是页面指针，活引用

`globalBackgroundPageId` 指向某一页；渲染取 `effectiveBackground(project, page) = 全局来源页背景 ?? 本页背景`。设置全局只改指针，不复制页面背景；来源页背景的修改立即影响所有页。取消只清指针，各页背景原样保留。后设置直接覆盖指针，无需先取消。

理由：与用户表述「设置为全局背景」一致，且取消后必然恢复各页背景。替代方案：设置时快照一份到项目槽位——改来源页不会影响全局，与用户预期冲突；复制到所有页——取消无法恢复，且会产生多份难以辨认的副本。

### D3：只读锁定而非自动取消全局

全局生效且 `page.id !== globalBackgroundPageId` 时，所有背景写入路径统一被守卫拒绝；UI 控件禁用并常驻原因，图层面板不提供图片子行；画布不命中背景。用户只能取消全局或勾选「所有页显示本页背景」让本页接管。接管控件不做二次确认。

理由：允许编辑但画面不变会制造「改了没反应」的假故障；自动取消全局会悄悄改变其它页。替代方案「编辑时询问只改本页/所有页」引入第三种状态与弹窗，且与用户已确认的规则冲突。

### D4：跨页复制 = 整页背景深拷贝

「复制背景…」弹窗列出其它页，按页渲染小预览（填充色 + 首图或全部叠图）。复制时按值克隆 `color` 与全部图片：图片条目重新生成 ID，`assetId` 保持共享，定位、顺序、调色、渐隐一并复制。目标页是全局来源时 toast 提示「所有页一起改变」；目标页被覆盖时入口禁用。

理由：避免背景片共享又保留「复制后各改各的」。资产共享沿用现有 `releaseUnusedAsset` 引用计数。

### D5：版本 4 与迁移链

项目 JSON 变为：

```json
{
  "version": 4,
  "globalBackgroundPageId": "page-1 | null",
  "pages": [{ "id": "page-1", "background": { "color": "#fff", "images": [] }, "elements": [] }]
}
```

迁移在 `project-schema` 加载阶段完成，先复用现有 v1/v2 → v3 的引用组折叠，再执行 v3 → v4：

1. 每个 `backgroundId` 对应背景集深拷贝到该页 `background`（图片 ID 保留原值即可，因为不再跨页共享）。
2. `unifiedBackground` 为真且有页面引用 `unifiedBackgroundId`：取第一页使用该背景的页面作为 `globalBackgroundPageId`。
3. `unifiedBackground` 为真但没有页面引用该背景：把该背景复制到第一页并令它成为来源页，保证画面不变（第一页原本隐藏的背景被替换，属于迁移取舍，记录在迁移说明）。
4. 其余情况 `globalBackgroundPageId = null`。
5. 未使用的背景集丢弃，引用它的资产不再进入 `collectReferencedAssetIds`。

草稿信封 `schema` 保持 1；`draft-store` 的项目版本上限从 3 改为 4，旧草稿经同一迁移路径恢复。`pruneMissingAssets` 改为遍历 `page.background.images`。

理由：单一路径、可单元测试；v1/v2 复用既有迁移，避免重写引用组逻辑。

### D6：选择与 UI 状态

- 选中类型移除 `backgroundSet`；保留 `backgroundImage`，但作用域是当前页（`{ type: 'backgroundImage', imageId }`）。选中页面/切换页清除背景选择。
- 页面属性「背景」分组是唯一编辑入口：缩略图、填充色、`更换背景`、`＋叠图`、`复制背景…`、`清空背景`、复选框「所有页显示本页背景」。
- 三种状态：无全局、本页是来源、别页是来源。第三种显示只读缩略图、`全局背景生效中 · 来源：第 N 页`、禁用的编辑控件与 `取消全局背景`；复选框仍可用（接管）。
- 图层面板可编辑页显示「背景 · N 张」+ 图片子行；被覆盖页只显示「全局背景 · 来自第 N 页」，点击跳到来源页并选中其背景。
- 页面标签只在来源页显示蓝色标记。来源页被删除时清空全局并 toast，撤销恢复页面与指针。
- 供复制弹窗使用的小预览由离屏 canvas 调用现有背景绘制函数生成，避免新增渲染路径；失败时退回色块 + 图片数量文字。

理由：属性面板是「这页的背景」的自然位置；图层面板用于进入画布编辑，不再承担库管理。替代方案：新增独立背景面板/抽屉——多一个入口与状态，与本变更目标相反。

### D7：写入守卫与撤销

所有背景写入集中经过 `assertPageBackgroundEditable(project, page)`（名称在实现时定），覆盖 `app-backgrounds`、`app-presets`、画布交互、方向键微调与文件拖入；拒绝时 toast 一次并保持数据不变。每个用户动作产生一条撤销记录：设/取消全局、复制背景、清空、整套替换、加图/替换/删除/换序、填充色与效果调整。删除来源页与清空全局合并为同一条记录。

### D8：预置整套应用改为替换

整套模式不再查找或创建「预置·X」背景集：用预置的建议填充色 + 该图替换当前页背景，一条撤销记录。`add`/`replace` 模式作用于当前页背景。预置清单、分块加载、物化去重、深色提示与体积门禁全部不变。

### D9：入口与文档清理

移除 `openBackgroundLibrary`、属性面板的 `管理背景库` 与两个下拉、`show` 相关样式与文案；`app-presets` 的整套分支删除按名称复用。同步 `README.md`、`AGENTS.md`、`docs/歌单生成器需求.md` 的背景章节，避免文档继续描述已删除的库。

## Risks / Trade-offs

- [共享背景语义消失] 旧项目里多页共用一个背景集，迁移后成为独立副本；只有全局停留期间保持同步。 → 迁移说明与取消全局后的行为在页面上可见；这是用户选择的规则，不额外做去重。
- [全局来源页被删除导致画面跳变] → 删除时 toast 明示并保留单步撤销；不提供「保留当前画面」确认，避免多一个分支。
- [被覆盖页控件大面积禁用显眼] → 用「本页背景（不显示）」+ 来源页 + 取消/接管两个出口组织成一个状态块，而不是零散禁用项。
- [迁移边界：全局背景无页引用、指针悬空、重复页面 ID] → 迁移与校验各自有单测；悬空指针导入直接报错，不猜测修复。
- [旧草稿版本门槛] → 只放宽项目版本上限，不改信封 schema；旧草稿在恢复时迁移，损坏分类逻辑保持。
- [复制弹窗预览成本] → 按需为可见行生成一次小图，缓存于弹窗生命周期；失败退化为色块。

## Migration Plan

1. 先落地 `model`/`project-schema`/`project-io` 的 v4 与迁移，再用现有 `node --test scripts/checks/*.test.js` 锁住结构与迁移。
2. 切换 `render`/`export`/`draft-store` 的读取路径；旧草稿与旧 JSON 夹具同时通过。
3. 切换 `app`/UI/预置链路，移除背景库入口与文案；手动回归导入、加页、拖分类、背景编辑、导出。
4. 更新文档与 `docs/歌单生成器需求.md`；`./build.sh` 重建 `dist/` 验证构建产物。

回滚：版本 4 的 JSON 不被旧版本接受；发布前保留 v3 分支，若需回滚需放弃 v4 项目文件或提供单独的降级脚本（不在本变更范围）。
