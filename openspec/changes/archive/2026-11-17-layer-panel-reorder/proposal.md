# Proposal

## Why

背景集里的图片已经有“上移/下移一层”，但入口只在右侧属性面板：用户必须先选中某张图片、再跑到检查栏底部找两个按钮。而自由图片在同一块图层面板里就有行内箭头，两者明明都是“同一容器内的兄弟层”，交互却不一样。图层列表本身又是只读的——不能拖、不能按键移动，图层行还是不可聚焦的 `div`，键盘用户无法进入列表。

## What Changes

- 图层面板的背景图片子行补上与内容行一致的 `↓` / `↑` 图标按钮：两端（最底、最顶）禁用，带可访问名称，点击后立即重排并就地刷新。
- 图层面板支持拖拽换序，**内容行与背景图片子行各自成一条独立列表**：可以拖动行到目标位置，落点用插入线（`drop-before` / `drop-after`，按行中点判定）；两个列表之间互相拒绝（不显示插入线、不产生任何改动），背景集行只作为分界线，本身不是落点。
- 图层行改成语义结构：外层 `div` 只负责边框/内边距/悬停与拖拽容器，行内改为“主按钮（图标 + 名称，原生可聚焦、Enter 选中、作为拖拽起点）+ 兄弟动作按钮”。行高、内边距、字号、图标位置与悬停反馈保持不变；嵌套按钮的非法结构随之消失，因此拖拽起点不需要再对箭头按钮做特殊拦截。
- 换序进入撤销栈：一次拖拽或一次按钮点击只产生一条撤销记录（`调整图层顺序` / `调整背景图片顺序`），在数组重排之前快照。撤销后的选区恢复从“只认内容元素”扩展到 `backgroundSet` / `backgroundImage`（对应 id 在快照中仍存在时保留），避免撤销一次换序后属性面板跳回页面。
- 重排算法抽成 `model` 纯函数：以“显示顺序的 id 列表 → 插入 → 反向写回”表达，禁止用 `len - 1 - displayIndex` 之类算术换算模型下标。
- 拖拽只作为指针增强：HTML5 拖放在触屏上不触发，触屏与键盘用户的换序路径是行内 `↓` / `↑` 按钮（内容行已有，背景图片子行本次补齐）。

**不包含**：拖拽时面板自动滚动、图层行缩略图、把“图片 N”换成素材文件名。

### Modified Capabilities

- `background-layer`: 「背景图片编辑」补齐顺序调整的完整入口（图层面板子行按钮 + 行拖拽），并明确三种入口共享同一次数组重排与单条撤销语义；「背景图片组合」的场景需要覆盖从图层面板拖拽换序。
- `editor-shell`: 「左侧歌单素材栏」增加图片子行的 `↓` / `↑` 图标按钮、两条列表各自独立的拖拽换序与插入线反馈、跨列表与背景集行的拒绝规则；「可操作行的原生语义」的“图层行 SHALL 使用原生可聚焦控件”本次真正落地（外框 + 主按钮），并补充拖拽起点与动作按钮的分离。
- `page-editor`: 「背景层与内容层」补充内容层级调整的拖拽入口与插入线语义，并明确背景层始终不进入内容 z-order、跨列表拖拽不产生效果。

## Impact

- `js/ui.js`：图层行结构（外框 + 主按钮 + 动作按钮）、背景图片子行新增箭头、两个列表的 `dragstart`/`dragover`/`dragleave`/`drop` 绑定与插入线切换；行点击守卫改为“主按钮负责选中”。
- `js/app.js`：新增 `moveLayerTo(fromIndex, toIndex)`（单条撤销）；`performUndo` 的选区恢复扩展到背景集/背景图。
- `js/app-backgrounds.js`：新增 `moveBackgroundImageTo`；`moveBackgroundImage` 补 `pushUndo`（该文件目前完全没有撤销入口）。
- `js/model.js`：新增按 id 重排的纯函数与显示序/模型序互转，供回归用例直接调用。
- `style.css`：`.layer-row` 拆成外框与主按钮两层（保持既有几何）、插入线（`box-shadow` 两条边）、拖拽光标。
- 测试：`scripts/checks/model.test.js` 覆盖重排纯函数（上移/下移/拖到首尾/拖到原位/单元素/空列表/显示序反转映射）；拖拽与落点属于 DOM 行为，零依赖套件覆盖不到，用 `agent-browser` 手测两条列表各拖一次、跨列表拒绝、按钮两端禁用、拖后撤销一次、刷新后顺序保留。
- 文档：`docs/歌单生成器需求.md` 背景层“每张图片独立设置…绘制顺序”一句补上图层入口；`README.md` 若有图层说明需同步。
- 无新增依赖、无构建步骤变化；草稿持久化沿用 `renderAll` → `redraw` 的 `dirty.draft` 排队，换序会自动落盘。
