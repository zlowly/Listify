# Proposal

## Why

当前字体设置把“西文字体”和“中文体”拆成两个槽位，再由 `fontPair` 组合成一条字体栈；对只想换一个字体的用户来说，入口、状态和持久化都过于复杂，而且同一套字体设置要在分类名、歌名和自由文字上分别重复配置。用户真正需要的是：一个按优先级排列的字体列表，以及新建同类子分区时自动沿用上一次的样式。

## What Changes

- **BREAKING（内部数据模型）**：移除双槽位 `fontPair`、`DEFAULT_LATIN_FONT` / `DEFAULT_CJK_FONT` 和“西文优先”组合逻辑；样式改用有序的 `fontFamilies: string[]` 作为字体选择来源，`fontFamily` 仅作为由列表派生出的 CSS 栈，供渲染、导出和旧版本兼容使用。
- 新建样式的字体列表默认为一项 `['sans-serif']`，界面显示为“系统默认”；列表 MUST 始终至少保留一项。
- 分类名、歌名和自由文字三处统一改为字体列表编辑器：
  - 点击某一行打开本机字体选择器并替换该行；
  - 提供“添加字体”，选择后追加到列表末尾；
  - 每行提供删除操作，只剩一项时删除不可用；
  - 列表顺序即 CSS 回退优先级，第一版不提供拖动排序。
- 支持 Local Font Access 的浏览器中，行内不提供任意字体名手输；不支持的浏览器降级为可编辑文本行，并保留底部手动添加输入。两条路径都遵守“添加 / 替换 / 删除 / 至少一项”的同一语义。
- 移除字体选择器的“西文 / 中文”槽位、槽位标题和字形覆盖提示；选择器统一标题为“选择字体”，使用中英混合示例预览，顶部“系统默认”返回 `sans-serif` 项。
- 新增分类块时，分类名子分区和歌名子分区分别深拷贝“上一个同类型子分区”的完整文字样式（字体列表、字号、粗细、颜色、行距、阴影、轮廓）；新增自由文字时深拷贝上一个自由文字的完整样式。样式是创建时的快照，之后修改源样式不会联动已创建的元素。
- 继承来源优先级：同页、位于新元素上方且距离最近者 → 同页最近者 → 整个项目文档顺序中最后一个同类型元素 → 默认样式。
- 项目保存写入 `fontFamilies` 和派生 `fontFamily`，不再写入 `fontPair`；加载旧项目时把已保存的 `fontFamily` 拆成列表行，保留原 `fontFamily` 渲染，不静默改写旧画面。项目版本号不升级，草稿 schema 不变。
- 同步更新 `DESIGN.md` 的字体策略、`PRODUCT.md` 的能力摘要和 `docs/歌单生成器需求.md` 的子分区字体说明。

第一版不做：字体行拖动排序、字体列表的跨项目全局复用、字体文件读取或上传、按字形覆盖自动筛选字体、把继承实现为实时联动。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `font-selection`: 字体入口从“西文 / 中文双槽位 + 可编辑完整字体栈”改为“有序字体列表 + 添加 / 替换 / 删除 + 至少一项”；选择器去掉槽位；持久化改为 `fontFamilies` + 派生 `fontFamily`，旧 `fontPair` 不再写回；保留授权、枚举、搜索、缓存、隐私和导出一致性要求。
- `category-layout`: 新增分类块时，分类名和歌名两个子分区分别继承上一个同类型子分区的完整文字样式，按同页最近优先、项目最后兜底的快照规则。
- `page-editor`: 新增自由文字时继承上一个自由文字的完整文字样式，同样按同页最近优先、项目最后兜底。

## Impact

- `js/model.js`：新增 `/ 调整` 字体列表归一化、列表与 CSS 栈互转、应用列表、旧栈拆分；移除 `fontPair` 组合函数；调整默认样式与元素创建时的样式继承。
- `js/ui.js`：替换 `fontField` / `bindFontField` 为字体列表编辑器，覆盖分类名、歌名和自由文字三处；变更后重绘并刷新属性面板。
- `js/fontpicker.js`：移除 `slot`、槽位标题、槽位示例和槽位默认栈；统一“系统默认”与混合预览。
- `js/io.js`：序列化 `fontFamilies` 与派生 `fontFamily`，停止序列化 `fontPair`；加载继续走 `normalizeStyle`。
- `js/app.js`：拖入分类和添加文字时把当前页 / 位置传给继承逻辑（或调用后应用继承样式）。
- `style.css`：用字体列表行、删除按钮、添加按钮和降级输入替换原 `.font-pair-*` 样式。
- `js/layout.js`：继承逻辑必须容忍自检用的伪项目（没有 `pages` 字段）。
- `DESIGN.md`、`PRODUCT.md`、`docs/歌单生成器需求.md`：同步字体列表与样式继承说明。
- 不新增构建步骤、依赖、后端或网络请求；仍可直接以 `file://` 打开。
- 无测试套件；验证方式为浏览器手动 / `agent-browser` 走查（详见 design 与 tasks）。
