# Design

## Context

见 `proposal.md`。当前拖入逻辑位于 `js/app.js` 的 `onDrop`：把遮罩层坐标经 `toPage` 换算为页面坐标后，以鼠标 `x` 居中生成块、以鼠标 `y` 作为顶边，仅做 `0` 边界与页宽裁剪。分类块默认宽度已经是内容区宽度（`pageSize.width - margins.left - margins.right`），但 `x` 仍可落在任意位置。

`js/layout.js` 已提供 `elementHeight(element, category)`：分类块按内容实时测量，自由文字按换行结果测量，自由图片读取自身 `height`，可直接复用来求物件底边。

## Goals / Non-Goals

**Goals:**

- 拖入创建时给出确定、可预测的落点：水平贴内容区左边距，纵向接在鼠标所在位置之前的内容之后。
- 落点计算与画布缩放、页面边距、现有元素高度保持一致，不新增持久化字段。
- 新增分类块不会覆盖鼠标上方（含鼠标所在）的已有物件。

**Non-Goals:**

- 不改变已有块的手动拖动、缩放、层级和属性编辑行为。
- 不提供拖拽过程中的落点预览或吸附参考线。
- 不对页面整体做自动排布，也不阻止块超出页面底边（溢出警告仍按原规则）。
- 不改变重复拖入、文件导入、页面切换等既有流程。

## Decisions

### 1. 水平位置固定为左边距

`x = margins.left`，不使用鼠标横坐标。分类块宽度固定为内容区宽度，这样左右边缘同时对齐左右边距。

- 备选：把鼠标 `x` 裁剪到内容区再居中。仍会随鼠标漂移，用户每次都要对齐，放弃。
- 备选：`x = clamp(mouseX - width / 2, margins.left, pageWidth - margins.right - width)`。在宽度等于内容区时结果与左边距相同，但引入无意义的计算分支，放弃。

### 2. 纵向候选为“顶边不高于鼠标”的所有物件，取最低底边

遍历当前页全部内容元素，筛选 `element.y <= cursorY`，计算每个元素的 `bottom = element.y + elementHeight(...)`，取 `max(bottom)` 作为新块顶边；候选为空时用 `margins.top`。

- 采用“顶边不高于鼠标”而不是“底边不高于鼠标”：鼠标落在某个物件内部时，该物件仍参与计算，新块落到它下方，避免直接覆盖。
- 不按水平重叠过滤：分类块默认横跨整个内容区，页面内绝大多数物件都会与之水平相交；按水平过滤反而会让落点依赖无关的窄元素。
- 备选：直接把鼠标 `y` 吸附到最近的物件底边（向上或向下都吸）。违反“鼠标上方”的语义，且鼠标落在空白处时会被拉到下方物件，放弃。
- 备选：仅底边低于鼠标的物件才算“上方”。会出现鼠标在块内时新块压住该块的情况，放弃。

### 3. 底边使用渲染高度，最终取整

分类块调用 `layout.layoutCategory` 的真实高度（经 `elementHeight`），自由文字用换行后的高度，自由图片用元素高度。`y` 最终取整并限制为不小于 `0`；不限制页面底边，保持现有溢出行为。

- 复用 `elementHeight` 而不是缓存值，保证与其他渲染路径一致；`_layout` 会在渲染时刷新，重复计算是幂等的。
- 分类元素需要传入 `model.getCategory(project, element.category)`；分类数据缺失时按空分类测量。

### 4. 定位逻辑内聚为一个纯函数

在 `js/app.js` 内新增一个小函数（如 `categoryDropPosition(page, project, cursorY, width)`），返回 `{ x, y }`；`onDrop` 只负责取分类、重复判断和创建元素。这样定位规则可单独阅读，也便于后续复用或调整。

## Risks / Trade-offs

- [鼠标在很高的物件内部时，新块会被放到该物件最底部，可能远离鼠标] → 这是“不覆盖已有内容”的直接代价；用户仍可手动拖动调整，规则本身保持可预测。
- [元素底边可能为负或超出页面] → 负值按 `0` 处理；超出页面不裁剪，继续由现有溢出警告提示。
- [复用 `elementHeight` 会触发一次额外排版计算] → 仅在 drop 时发生一次，成本可忽略。
- [已有项目加载后，旧块位置不迁移] → 本变更只影响新拖入的落点，保存的坐标原样保留，符合非目标。
