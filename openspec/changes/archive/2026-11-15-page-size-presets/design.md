# Design

## Context

页面尺寸在属性面板中目前由两个数字输入和两个固定按钮组成：输入下限写 200，但 `setPageSize` 实际把宽高收敛到 320–5000；两个按钮只覆盖 1080×1920 与 1920×1080。`project.pageSize` 是项目级唯一事实源，默认 1080×1920，随项目持久化，没有预设 id 字段。现有规格要求改尺寸时所有页面生效、元素保持坐标、背景按 fit 模式回流。需求与范围见 `proposal.md` 和 `specs/page-editor/spec.md`。

## Goals / Non-Goals

**Goals:**

- 用原生下拉提供 1080P/2K 横竖四个常用尺寸，同时保留任意宽高输入。
- 下拉状态始终由当前宽高推导，不新增持久化字段，不产生迁移。
- 选择预设或交换宽高只写入一次、只产生一步撤销。
- 宽高输入与 `setPageSize` 共用同一范围，消除 200/320 不一致。
- 预设匹配与范围常量可被 Node 用例覆盖。

**Non-Goals:**

- 不自动缩放、重排或迁移已有元素；不改变“元素保持坐标”的现有语义。
- 不新增 4K 画布、方形、长图或页面拼接预设；4K 仍由导出对话框处理。
- 不把下拉做成模式：不隐藏输入、不需要先点“自定义”才能编辑。
- 不改页面尺寸的持久化结构、项目级语义或导出对话框的自定义尺寸能力。
- 不引入自定义下拉组件或新依赖。

## Decisions

### 1. 预设表、范围常量与匹配函数放在 `js/model.js`

在 `L.model` 中新增：

```
PAGE_SIZE_MIN = 320
PAGE_SIZE_MAX = 5000
PAGE_SIZE_PRESETS = [
  { id: '1080p-portrait',  label: '1080P 竖屏', width: 1080, height: 1920 },
  { id: '1080p-landscape', label: '1080P 横屏', width: 1920, height: 1080 },
  { id: '2k-portrait',     label: '2K 竖屏',    width: 1440, height: 2560 },
  { id: '2k-landscape',    label: '2K 横屏',    width: 2560, height: 1440 }
]
matchPageSizePreset(width, height) -> preset | null
```

理由：`model.js` 已经拥有默认页面尺寸和 `clamp`，预设是页面领域数据；纯函数可在 `model.test.js` 中直接覆盖，不需要新增脚本或扩大 UI 文件。`model.js` 当前 818 行，增加约 30 行仍低于 900 行上限。备选“放在 `ui-property-panel.js` 的局部常量”无法在 Node 中测试，且 `setPageSize` 拿不到同一份范围；备选“新建 `js/page-presets.js`”为一小段静态数据引入新的加载顺序，收益不足。

### 2. 预设集合按手机壁纸，2K 采用 9:16

提供 1080P 竖/横与 2K 竖/横；2K 竖屏为 1440×2560，横屏为 2560×1440，与现有 1080P 的 9:16 比例一致。现代 20:9 手机（如 1440×3200）不单列预设，用户可直接输入或用交换按钮得到。

理由：用户明确目标是手机壁纸，且不再需要歌单长图；四个预设覆盖最常见的 1080P/2K 横竖，不引入方形、4K 或长图等未确认需求。备选“加 20:9”会让下拉变长且无法覆盖所有机型；“按设备品牌列预设”不可维护。

### 3. 下拉是快捷入口，宽高输入始终可见

页面尺寸分组结构为：预设 `<select>`、宽度输入、高度输入、交换按钮。`project.pageSize` 仍是唯一事实源，不保存 `presetId`，不引入“自定义模式”。每次渲染时：

- 若宽高精确匹配预设，`select.value` 为该预设 id；
- 否则 `select.value = 'custom'`，选项文字渲染为 `自定义 1200×1800`；
- 选择预设 → 用该预设宽高调用一次 `setPageSize`；
- 选择“自定义” → 只聚焦宽度输入，并把 `select.value` 立即重置为当前推导值（当前尺寸仍匹配预设时不会假装进入自定义状态）；
- 修改任一宽高 → `setPageSize` 后重新渲染，`select` 自动落到匹配预设或自定义。

理由：这样既有常见尺寸的可发现性，又保留直接输入；不隐藏输入，避免“先点自定义才能编辑”的额外一步和“加载自定义项目要自动展开”的状态机。备选“下拉 + 隐藏输入”需要维护上次自定义值，且加载时必须自动切到自定义；备选“只保留输入”缺少预设发现性。

### 4. 一次写入、一步撤销

预设选择调用 `setPageSize(preset.width, preset.height)`，交换按钮调用 `setPageSize(project.pageSize.height, project.pageSize.width)`，宽高输入分别调用一次 `setPageSize`。不得先写宽度再写高度，否则会产生两条撤销记录。

`setPageSize` 继续负责 `pushUndo('修改页面尺寸')`、取整、范围收敛和 `ui.renderAll()`；UI 不直接改 `project.pageSize`。属性面板重渲染后由现有焦点恢复逻辑保持输入焦点；选择“自定义”只做聚焦，不触发重绘。

### 5. 统一范围 320–5000

`PAGE_SIZE_MIN`/`PAGE_SIZE_MAX` 同时用于：

- 两个数字输入的 `min`/`max`；
- `setPageSize` 的 `clamp`；
- 预设匹配前的取整结果。

现有输入写 200、逻辑却收敛到 320，属于界面与行为不一致；统一到 320 后，用户输入 200 会在提交时变成 320，与既有实际行为一致，不构成新的数据限制。若历史 JSON 项目带有小于 320 的尺寸，属性面板按原值显示为自定义，直到用户修改时再按统一范围收敛，不在加载时静默改数据。

### 6. 使用原生 `<select>`，不引入自定义控件

预设下拉用原生 `<select>` 与 `<option>`，保留键盘、读屏和平台选择器行为；样式只做宽度和高度对齐。交换按钮使用文本 `⇄`，带 `aria-label="交换宽高"` 与 `title`。项目已有 `ui.selectInput` 工厂时优先复用其结构，但保持原生元素语义。

理由：项目约束明确优先平台语义，避免 `popover` 等非 Baseline API；四个选项不需要搜索或分组。

### 7. 页面尺寸变化的既有语义不变

切换预设只改 `project.pageSize`，所有页面随项目设置变化；元素坐标不缩放、不重排；`cover`/`fill-width`/`fill-height`/`original` 背景按现有渲染逻辑回流，`none` 背景保持固定矩形；画布缩放级别不重置。导出对话框默认值继续取当前页面尺寸，因此选 2K 后默认导出 2K，仍可在导出时改宽高。

### 8. 性能

2K 画布（1440×2560）像素量约为 1080P 的 1.78 倍。改动只影响属性面板的一次重渲染和既有 `renderAll()`，没有新增逐帧计算或 DOM 列表。需要在浏览器中确认 2K 下拖动/缩放仍流畅、导出耗时可接受；若出现明显退化，再单独优化渲染，不在本变更中扩大范围。

## Risks / Trade-offs

- [2K 采用 9:16，而部分手机是 20:9] → 下拉保持四个常用预设，20:9 通过宽高输入或交换按钮得到；规格不承诺覆盖所有机型。
- [用户以为换预设会自动缩放内容] → 规格和场景明确“元素保持原有坐标”；这是现有行为，不在本变更中改变，避免牵连排版与背景语义。
- [“自定义”选项看起来像持久模式] → 它只聚焦输入并立即把下拉重置为当前推导值；只有宽高真正不匹配预设时才显示自定义，选项文字带当前尺寸。
- [精确匹配导致 1080×1921 显示自定义] → 这是预期：预设只在完全一致时命中，避免四舍五入或容差造成“显示 1080P 但实际不是”的错觉。
- [历史项目尺寸小于 320] → 加载时保留原值并显示自定义，用户修改时才收敛；不静默改数据。
- [2K 渲染/导出变慢] → 在浏览器矩阵中覆盖 2K 的拖动、缩放与导出；如有问题单独优化，不回退预设。
- [属性面板重渲染丢失焦点] → 复用现有焦点捕获/恢复；自定义选项只聚焦不重绘，预设选择后焦点回到下拉。

## Migration Plan

1. 在 `js/model.js` 增加预设、匹配函数与范围常量，并在 `model.test.js` 固定行为。
2. `js/app.js` 的 `setPageSize` 改用共享常量，保持一次撤销与全页生效。
3. `js/ui-property-panel.js` 用下拉 + 输入 + 交换按钮替换两个固定按钮，绑定一次写入。
4. `style.css` 调整下拉与按钮布局。
5. 运行 `node --test scripts/checks/*.test.js`，再用浏览器验证预设、自定义、交换、撤销、全页生效与 2K 导出。
6. 无数据迁移、无 feature flag；回滚即还原文件，已有项目尺寸不变。

## Open Questions

无。20:9 是否加入预设、是否自动缩放内容都属于后续独立需求；当前方案不依赖它们的答案。
