# Proposal

## Why

页面尺寸现在只有“纵向 1080×1920 / 横向 1920×1080”两个按钮：手机壁纸常用的 1080P 与 2K 尺寸无法一键切换，用户只能手填宽高，既容易记错，也看不出当前属于哪个预设。把固定按钮改成预设下拉，同时保留任意尺寸输入，可以让常见尺寸可发现、可切换，也不牺牲自定义能力。

## What Changes

- 页面尺寸区改为“预设下拉 + 宽高输入 + 交换宽高按钮”；下拉包含 1080P 竖屏、1080P 横屏、2K 竖屏、2K 横屏与“自定义”。
- 默认尺寸仍为 1080×1920；页面尺寸仍是项目级设置，修改后作用于所有页面。
- 下拉是快捷入口，不是模式：宽高输入始终可见。当前宽高与某个预设完全一致时显示该预设，否则显示带当前尺寸的“自定义 1200×1800”。
- 选择“自定义”只把焦点移到宽度输入，不隐藏输入、不打开弹窗；修改任一宽高后，下拉立即反映为匹配的预设或自定义状态。
- 选择预设一次写入宽高并只产生一步撤销；新增交换宽高按钮，同样是一步撤销。
- 统一宽高允许范围为 320–5000 像素，修复当前输入框下限 200 与 `setPageSize` 实际下限 320 的不一致。
- 页面尺寸变化不自动缩放或重排已有元素；背景按现有规则回流。范围外不新增 4K 画布、方形或长图预设，4K 输出仍走导出对话框。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `page-editor`: `全局页面尺寸` 增加预设下拉、自定义状态、交换宽高、统一范围与单步撤销；默认尺寸、项目级语义和“元素不自动重排”保持不变。

## Impact

- `js/ui-property-panel.js`：页面尺寸分组改为下拉、宽高输入与交换按钮，并同步当前预设状态。
- `js/model.js`：新增页面尺寸预设表、匹配函数与宽高范围常量，供 UI 与 `setPageSize` 共用。
- `js/app.js`：`setPageSize` 使用统一范围常量，保持一次撤销与全页生效。
- `style.css`：下拉与交换按钮的轻量布局调整。
- `scripts/checks/model.test.js`：覆盖预设匹配、默认值与范围常量；页面交互仍按项目约定在浏览器中手工/自动化验证。
- 不新增依赖、不改草稿结构或 IndexedDB schema；已有自定义尺寸的项目加载后直接显示“自定义”。
