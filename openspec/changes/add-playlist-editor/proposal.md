# Proposal

## Why

导入后的歌单目前只能整份重新导入才能修正个别错字或增删歌曲；重新导入需要回到源文件，且按分类名匹配，改名会被当成旧块删除。用户需要一个不离开应用、只做小范围修正的入口，同时不破坏已经排好的版面。

## What Changes

- 在左侧分类视图的工具栏增加「编辑歌单」入口，打开一个宽弹窗。
- 弹窗左侧是分类导航，右侧是当前分类的多列歌名网格；单击即可改分类名或歌名。
- 支持：分类改名；歌名新增、修改、删除；粘贴多行批量新增歌名。
- 分类改名在应用时同步改写所有页面中 `element.category` 的引用，保留块的位置、尺寸、样式、表格结构与手动列宽。
- 编辑基于内存中的工作副本，只有点「应用」才写回项目；「取消」或关闭弹窗完全丢弃修改。
- 校验规则与导入保持一致：分类名非空且唯一；歌名全局唯一、非空、不以 `#` 开头；允许分类名与歌名同名；允许把分类清空为 0 首。
- 明确不支持：分类新增/删除、歌曲跨分类移动或排序、搜索、文本镜像模式、撤销栈、实时预览。
- 不改变项目数据模型、保存格式或导出行为，不新增依赖。

## Capabilities

### New Capabilities

- `playlist-editing`: 在应用内对已导入歌单做分类改名与歌名增删改，包含入口、编辑界面布局、校验规则、工作副本与应用/取消语义、以及分类名变更对画布块引用的迁移。

### Modified Capabilities

<!-- 无：现有 playlist-import、editor-shell、category-layout 的需求不需要改写。 -->

## Impact

- `index.html`：分类工具栏新增「编辑歌单」按钮；无歌单时按钮禁用或提示先导入。
- `js/ui.js`：新增编辑器弹窗、分类导航、歌名网格、校验状态与键盘/鼠标交互。
- `js/app.js`：打开编辑器；应用时按 `originalName -> name` 迁移页面上所有分类块引用，替换 `project.playlist.categories`，修正选中态并调用 `ui.renderAll()`。
- `js/model.js`：可能新增歌名校验等纯函数或复用现有 `clone`；不改变项目结构。
- `style.css`：编辑器弹窗、分类栏、网格单元格、错误态与窄屏适配样式。
- `docs/歌单生成器需求.md`：补充「编辑歌单」入口、可编辑范围，以及分类改名保留已放置块版面的说明。
- 不改 `js/import.js`、`js/layout.js`、`js/render.js`、PNG 导出与项目持久化格式。
- 仍为零构建、纯本地、`file://` 可运行；无新增运行时依赖。
