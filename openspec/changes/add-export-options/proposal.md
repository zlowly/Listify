# Proposal

## Why

现在只能导出当前页，而且总是把背景层一起导出。歌单常常跨多页，逐页导出要在页签之间来回切换；把歌单文字叠到别的背景上时，现有导出也给不出透明底、只含分类块的 PNG。这两个限制都来自第一版的刻意取舍，不是技术约束。

## What Changes

- 导出对话框增加“导出范围”：本页 / 所有页。
- 本页导出仍为单个 PNG；所有页导出打包为一个 ZIP，内含逐页 PNG。ZIP 用 store（不压缩）在项目内生成，不引入新依赖。
- 导出对话框增加“导出内容”：完整页面 / 仅歌单层（透明底）。
- 透明模式：画布保持页面尺寸、alpha 为 0，只绘制分类块（分类名 + 歌名表格），不绘制背景、自由文字、自由图片；仍按页面边界裁剪。
- 透明模式下没有分类块的页面在“所有页”导出中跳过，并在结束时报告页码。
- 所有页且项目只有 1 页时，直接导出 PNG，不为一张图打包。
- 文件命名：`歌单_第3页.png`、`歌单_第3页_透明.png`、`歌单_8页.zip`、`歌单_8页_透明.zip`；ZIP 内条目按页码补零，例如 `歌单_第01页.png`。
- 多页导出失败时不产生 ZIP；单页失败时不产生文件。
- 删除 `png-export` 中“第一版 MUST NOT 导出全部页面或打包多个文件”的限制。

## Capabilities

### New Capabilities

（无）

### Modified Capabilities

- `png-export`: 导出范围、透明歌单层模式、多页 ZIP 打包、命名与失败处理。

## Impact

- 代码：`js/export.js`（对话框、范围/内容模式、批量流程）、`js/render.js`（`drawPage` 支持跳过背景与按元素类型过滤）、`js/model.js`（`downloadBlob` 的 URL 回收时长）、`style.css`（对话框控件样式，如需）。
- 依赖：无新增；ZIP 由项目内代码生成（store + CRC32）。
- 数据：项目 JSON 结构不变，不新增持久化字段。
- 规范：`openspec/specs/png-export/spec.md` 将被更新。
- 兼容：已有单页导出行为保留；默认范围为本页、默认内容为完整页面。
