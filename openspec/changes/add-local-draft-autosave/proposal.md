# Proposal

## Why

当前项目只存在于内存中，刷新或关闭页面会清空所有歌单、页面、版面和背景；用户每次都要重新导入歌单并重新排版。现有“保存项目 / 加载项目”本质是文件下载与文件替换，不能承担“继续上次工作”的日常路径；需求文档也已提到可用 localStorage 存草稿。

## What Changes

- 新增当前工作区自动草稿：编辑后自动保存，重新打开页面时自动恢复页面、元素、歌单、背景库、图片资产和当前页。
- 草稿采用浏览器本地存储：项目结构写入 localStorage（同步、刷新立即恢复），图片资产写入 IndexedDB（避免 localStorage 约 5MB 配额被 base64 图片撑爆）。
- 顶栏动作改为“新建项目 / 导入项目 / 导出项目 / 导出 PNG”；导入和新建都只做普通确认，覆盖当前草稿且不可撤销。
- “保存项目”重命名为“导出项目”，“加载项目”重命名为“导入项目”；导出格式仍为现有 v3 JSON，旧文件可直接导入。
- 新增草稿状态提示：显示最近保存时间；存储失败时明确提示，但不阻塞编辑和导出。
- 草稿结构损坏时回退到空白项目并提示，不静默加载坏数据。
- 多标签页先按最后写入者覆盖处理，作为已知限制记录在设计文档中。
- 不新增后端、构建步骤或运行时依赖；`file://` 直接打开仍可用。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `project-persistence`: 新增草稿自动保存、启动恢复、存储失败与损坏降级要求；把保存/加载的文件动作表述为导出/导入。
- `editor-shell`: 顶栏项目动作集合改为新建/导入/导出项目与导出 PNG，并允许草稿保存状态文案。

## Impact

- `index.html`：顶栏按钮与文案。
- `js/app.js`：启动时恢复草稿、编辑后的自动保存调度、新建/导入/导出动作、草稿状态。
- `js/io.js`：草稿结构序列化与恢复，复用现有 v3 校验、迁移和图片资产构建路径。
- `js/ui.js`：按钮绑定与提示文案。
- `js/model.js`：如需在图片资产加入时写入 IndexedDB，补充资产持久化钩子。
- 无新增依赖、无后端、无网络请求；仅使用浏览器 localStorage 与 IndexedDB。
- 验证方式仍为浏览器手动/`agent-browser` 走流程，无测试套件。
